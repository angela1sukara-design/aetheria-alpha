# 可直接交付的工程任务指令

你要继续现有《以太都市：深渊重塑》Alpha 0.2 工程，接入并验证通用可选正文槽。请先阅读本包全部规范并检查最新源码；本包记录的基线为 `daf1a45`，最新代码若有差异，以实际源码为准并报告差异。

本任务只处理槽位的数据结构、注册、上下文、显示开关、回退、测试和存档兼容。所有演示正文使用中性占位句，不生产成人情节或正文。不要重写 NPC、TF、事件、身体或存档系统，不要求用户设计人物剧情。

按以下顺序一次完成并统一交付：

1. 检查 Git 状态及工程约束，保存可恢复检查点，在独立分支工作。保留其他任务尚未完成的修改，不将无关修改混入提交。
2. 读取 `src/core/district-types.ts`、`src/content/district-schema.ts`、`src/content/text-variants.ts`、`src/content/loader.ts`、`src/content/append-only.ts`、`src/engine/writing-context.ts`、`src/engine/selectors.ts`、`src/engine/npc.ts`、存档校验及相关测试。
3. 运行 `verify.test.mjs`。先证明本包的中性示例能注册、进入事件、替换正文、回退、退出、保存和读档。不要将示例默认放进正式世界。
4. 根据 `02-待补接口与验收.md` 实施最小的通用修补：节点与槽的唯一绑定、参与者一致性、出口一致性、年龄资格一致性。先明确错误码与负例测试，再补校验。避免仅在 UI 中检查。
5. 如果扩展动态 NPC，设计版本化的参与者引用和统一只读解析接口，使固定 NPC 与世界内稳定 NPC 实例共享文本入口。沿用当前记忆和身份数据，不在渲染时生成新 NPC；未知引用应失败或回退。不要把实例 ID 冒充 Registry 定义 ID。
6. `sceneRequirements` 等描述性字段目前没有执行语义。需要条件时使用引擎已有条件；如必须新增语义，单独设计版本化契约和测试，不能用自由文本当脚本。正文中的描述不能写入身体、接触、关系或记忆。
7. 保留 `rating: adult` 现有拒绝行为，报告它与 Alpha 0.2 角色资料协议之间的未完成衔接。若未来要改变事件评级协议，应另立协议版本和兼容测试；不得删除校验或改成 `general` 绕开。此包的 `general` 示例是中性的技术测试。
8. 验证旧内容包和旧存档。包集合变化不等于存档自动兼容；拿不准时保留原存档并按现有隔离流程处理，不能静默丢字段、重抽世界或重建人物。
9. 执行项目类型检查和完整测试；若修改运行时代码，再构建并检查离线游戏。交付源码、测试结果、示例、Git 检查点和未实现清单，清楚区分已实现与仅有规范的接口。

正文包保持 `prose_only`。不得加入行动效果、概率、NPC 行为树、身体补丁、外部 AI API 调用或生成器逻辑。当前 `priority` 只是已有文本选择接口中的优先级，不属于基础词条字段。

无需分批向用户交付每个槽位；一次完成上述工程范围并交付可验证结果。如源码冲突，说明具体文件与最小解决方案，不直接重构整个工程。
