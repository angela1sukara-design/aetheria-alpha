# 当前槽位接口：已实现与未实现

以下按基线 `daf1a45` 源码核对。名称相近不代表协议相同。

## 1. 注册槽与提供正文是两种文件

**ContentPack** 注册 NPC、事件、行动与 `textSlots`，由 `loadPacks()` 在建 Registry 时加载。新槽必须先注册。示例 `examples/slot-content-pack.json` 是完整内容包，不能通过“导入可选文本包”按钮加载。当前 UI 的 append-only 事件包导入也不接受新 `textSlots` 或新 NPC。

**TextExpansion** 只向已经注册的槽提供正文。可以在游戏的内容偏好面板导入、启用、禁用和移除。它不创建 NPC、事件、行动或世界状态。

本包示例在验证程序内组合六个正式内容包与测试包；正式游戏默认内容清单保持原样。若工程 AI 要做独立测试构建，应显式增加测试入口，避免影响原有玩家。

## 2. TextSlotDef 全部字段

字段名必须与当前结构一致；示例含完整对象。

| 字段 | 当前含义与限制 |
| --- | --- |
| `id` | 全局唯一的 `namespace:id`；不能改变已有槽 ID 的含义 |
| `owner` | `{ eventId, nodeId }`，事件和节点必须存在 |
| `contentTier` | 仅 `mature_fade` 或 `adult_optional`；没有 `explicit` 枚举 |
| `fallbackTextKey` | 已注册文本键；必须能在关闭开关、缺包或条件不足时独立使用 |
| `participants` | `player` 或固定 NPC 的定义 ID；动态 NPC 实例引用尚不支持 |
| `allowedVariables` | 仅支持 `player.name`、`npc.displayName` 两种替换变量 |
| `requiredFacts` | 已注册 flag ID；全部为真时才选替换正文，不控制事件能否进入 |
| `sceneRequirements` | 字符串数组，目前只是说明，不能执行条件 |
| `before` / `after` / `purpose` | 作者参考说明，目前不执行或验证其叙事内容 |
| `requiredBeats` | 必需叙事要点的文字说明，目前不自动审核正文是否满足 |
| `nextNodeId` | 必须存在的同事件节点；实际推进仍由行动效果执行 |
| `exitActionIds` | 必须是已注册行动；实际退出仍由事件行动执行 |
| `allowedReplacement` | 固定为 `prose_only` |

当前显示器和上下文导出器会取匹配事件节点的第一个槽。全局 ID 唯一已检查，**同一个事件节点上不能绑定两个槽**目前仅是接入要求，尚无统一强制校验。参与者与事件参与者、出口与实际路径的一致性也需补齐。

## 3. TextExpansion 全部字段

```json
{
  "manifest": {
    "id": "slot-integration/placeholder-prose",
    "namespace": "slotprose",
    "version": "1.0.0",
    "worldVersion": "0.2.0"
  },
  "variants": [
    {
      "slotId": "slotdemo:textslot.placeholder",
      "textKey": "slotprose:text.placeholder",
      "text": "【可选正文占位】{player.name}与{npc.displayName}确认本次展示仅用于接口验证。",
      "tier": "adult_optional",
      "priority": 20,
      "reviewStatus": "approved"
    }
  ]
}
```

- 根对象、manifest 和每条 variant 都是精确字段集合；不能添加 `effects`、`conditions`、自定义评级等字段。
- `namespace` 使用小写字母开头，后续小写字母、数字、下划线或连字符；`textKey` 必须以该命名空间加冒号开头。
- `version` 为三段数字；`worldVersion` 当前必须为 `0.2.0`。
- 每包最多 100 条 variant；同一包内一个槽只能有一条。
- `text` 非空，最多 10,000 个 JavaScript 字符串长度单位（UTF-16 code unit）；只允许槽声明的 `{变量}`。
- `tier` 仅为 `general` 或 `adult_optional`；后者只能放在 `adult_optional` 槽里。
- `priority` 是 0–100 的整数。同一槽在不同已安装包中使用相同优先级会冲突；选择时按优先级降序，再按文本键排序。
- `reviewStatus` 当前必须为 `approved`。这是文件中的声明，不代表引擎进行了语义审核。示例只有经核对的中性占位句。
- UI 单文件限制为 1 MiB。大量词条素材沿用独立词库交付，不能装进这个 100 槽上限的运行时文件。

## 4. 当前显示门槛

替换正文先要求 `requiredFacts` 全为真。`general` 正文无需成人偏好；`adult_optional` 正文还要求：

1. 玩家资料 `created` 为真且年龄至少 18。
2. 用户已开启 `profile.adultOptional`。
3. 所有非玩家参与者能在 Registry 中解析为固定 NPC，并通过现有成年资格检查。

现有 NPC 成年检查按其物种 `adultAgeYears` 判定，未知年龄或非智慧物种不合格。**它目前没有统一叠加 NPC 的 18 岁下限**，未来接入应要求 `ageYears >= max(18, species.adultAgeYears)` 并补测试，不能把当前检查说成已经满足此规则。

关闭开关、没有正文包、条件不足或正文包被禁用时显示 `fallbackTextKey`。回退正文没有上述开关保护，所以必须是安全且独立成立的中性文字。`mature_fade` 槽只接受 general variant，本身没有特殊显示门槛。

## 5. 真实上下文与权威状态

在已进入开放槽的事件节点时，内容偏好面板可以导出当前上下文：槽 ID、所属节点、时钟、位置、玩家资料和身体、固定 NPC 定义与状态、所需 flags、当前 scene、允许变量和下一节点。没有开放槽时导出失败。

- `{npc.displayName}` 当前只取第一个非玩家参与者；多 NPC 的命名变量尚未支持。
- 固定 NPC 的导出记录包含定义、关系和记忆，不等于每个 NPC 都已经有独立 BodyGraph。当前 scene 的身体数据只在场景存在时可用；缺失不能靠文字补造。
- 输出不得泄露不应公开的人物秘密或世界谜题；上下文是受控创作资料，不是玩家日志。
- `TextLibrary` 只参与只读显示。安装、切换、替换或移除正文不能推进时间、消耗 RNG、写入记忆、改变关系、创建接触或应用 TF。
- 文本包与游戏存档分离保存；换设备读档没有文本包时，应保持同一游戏状态并使用回退文字。

## 6. 不能误称为已完成的能力

`EventDef.rating` 虽定义了 `general | adult`，当前加载器仍拒绝所有 `adult` 事件，错误码 `ADULT_PLAYER_UNVERIFIED`。Alpha 0.2 的玩家资料和可选文本偏好已经存在，但完整事件评级协议尚未接通。

本包示例是 `rating: general` 的中性接口测试。它不展示实际成人玩法，也不能作为改低真实内容评级的办法。新增评级、新器官或新接触行为需要独立的版本化引擎能力，不能靠增加正文、修改 JSON 字符串或把素材标签当效果实现。

## 7. 对应源码

在工程根目录查看以下文件即可复核，不需要阅读固定人物的隐藏情节：

- `src/core/district-types.ts`：槽类型。
- `src/content/district-schema.ts`：槽字段及引用验证。
- `src/content/schema.ts`、`src/content/loader.ts`：完整内容包、事件和 NPC 的验证。
- `src/content/append-only.ts`：UI 事件扩展的边界。
- `src/content/text-variants.ts`：正文包校验、选择和显示资格。
- `src/engine/selectors.ts`、`src/engine/writing-context.ts`：节点选择和上下文导出。
- `src/engine/npc.ts`：固定 NPC 身份、日程和成年资格。
- `src/persistence/codec.ts`、`src/persistence/district-validation.ts`：存档与角色资料校验。
