# 以太都市：基于工程 Tag 的战斗与故事写作规范

版本：1.2｜核对日期：2026-10-15｜用途：交给其他 AI 的写作任务说明。

默认交付改为 **槽位模板 + 词条入槽资料 + 拼装校验**，完整 `prose` 仅作回退。必须附独立 `assembly-rules.json`，矩阵 cell 只挂 `assemblyRuleId`；冻结 place / propEnv / bodyPart / senseMod / actionCore / materialFluid / opponentForm / exitChoice 八类槽。词条须写 allowedSlots、priority、审核、实例绑定、互斥；定词仅在 materialFluid 槽内挂前。禁止笛卡尔写作穷举，失败整段普通回退，T32/T34 在选词前与拼装后复核。完整新契约见 [槽位拼装规范](../docs/reference/prose-slot-assembly-standard.md)，其内容优先于下文旧整段稿格式。离线拼装工具已提供，游戏接口尚未接入，不能直接给现有 ContentPack 增加这些字段。

这是编辑与交付规范。组合故事接口现已实现于`src/core/adventure-types.ts`，默认样例见`content/adventure/pack.json`，完整说明见[故事与成长框架](../docs/reference/adventure-framework-2026-10-13.md)。本文的Markdown节点卡与可见标记仍不会自行执行，需转成真实内容包契约；用户指定范围和已确认设定优先，不得凭创作补造工程能力。

## 1. 给写作 AI 的任务

你为当前工程编写中文战斗记录和可组合的故事节点。先查证工程里的标签、词条、事件与真实状态，再写正文。目标是让多个敌人和人物复用节点，同时保留能力、目标、倾向、身体和环境造成的差异。

每次任务先声明模式：

- `existing-prose`：扩写已有事件。严格保留原条件、动作、效果、节点顺序、出口和权威事实。
- `runtime-nodes`：使用已实现的NarrativeNode/Profile接口设计节点。条件和效果必须来自当前契约；交付节点卡，委托明确要求JSON时再提交完整且可校验的包。
- `proposed-nodes`：设计尚未支持的能力。只有超出当前接口的新条件、状态、倾向、动作或效果才列为待实现项。

没有特别委托时交付带依据标注的 Markdown 制作稿，同时附有序 proseTemplate、独立规则、入槽词条、完整普通 prose 回退与拼装预览/失败报告。不要把故事节点塞进纯素材批次，不要自行修改游戏代码、原始词库、登记新 TagDef 或标记 approved；独立制作 JSON 不是游戏 ContentPack。

## 3. 四种依据必须分开

| 类型 | ID 或来源 | 可以做什么 | 不能证明什么 |
|---|---|---|---|
| 运行标签 T | 实际加载包中的 active TagDef，例如 `foundation:theme.gel` | 表示定义规定的主题或查询语义 | 有主题不证明身体、动作或事件已经发生 |
| 素材引用 L | 真实素材 ID，例如 `lx.body-accessory.b0001.0002` | 提供物件、动作或描写素材 | 素材存在不证明本局有该物件或能力 |
| 编辑概念 E | 离线 taxonomy 中的 ID，例如 `general-taxonomy:disposition.caution` | 编辑选材和设计差异 | 不属于已安装运行标签，不会自动驱动行为 |
| 情境事实 F | 当前快照、原事件正文、行动效果或已确认的任务输入 | 约束本次真实处境 | 不能把“可能发生”写成“已经发生” |

未找到的必要概念使用 P 类“提案”，放入缺口清单；不得自造貌似正式的 `foundation:*`、`lx.*` 或 `general-taxonomy:*` ID。

已查实的例子：

- `foundation:theme.gel` 是黑胶题材；`foundation:material.gel` 是材料定义；两者不是同类 ID。
- `foundation:body.mechanical-tail` 表达派生身体语义；角色是否满足，需要真实身体查询结果。
- `general-taxonomy:disposition.caution` 是“谨慎”的离线编辑概念，状态为 proposed-editorial。
- `lx.body-accessory.b0001.0002` 是“细铜丝耳圈”素材，来源为 collections/body-accessory/body-accessory.b0001.json。
- `lx.nsfw-action.b0002.0001` 是“缠绕”动作素材，来源为 docs/tag-hub/nsfw-batches/nsfw-action.b0002.json；它不是角色“已被缠绕”的状态定义。

默认加载、可选试跑、已归档素材、待审编辑概念要分别记录。`tagcoexist:*` 属于可选试跑内容，不能假定默认局已安装。词库里的中文 tags 也不能直接当作 v2 稳定 TagDef ID。

## 4. 正文标记与依据表

审稿版必须在相关描写后直接标记依据。统一使用 `【T1】`、`【L1】`、`【E1】`、`【F1】`、`【P1】`；编号只在当前文档内有效，不是游戏 ID。

每份稿件开头提供依据表：

| 标记 | 名称与真实 ID/事实 | 来源路径及条目/节点 | 作用对象 | 审核/安装/核验状态 |
|---|---|---|---|---|
| T1 | 黑胶题材：foundation:theme.gel | tag-dictionary.json；按 ID 查找 | 故事题材 | active；默认 foundation 包；已核验 |
| F1 | 某角色实际穿着外衣 | 指定快照中的穿着记录或已确认事件事实 | 该角色的外衣 | 本次已确认；不能由题材推出 |

标记贴近所支撑的句子。同一事实连续描述可在段末标一次；一句混合几个关键依据时分别标记。普通连接词无需标记。

所有影响行动、身体、关系、物品、进度和结局的陈述必须可追溯。T/L/E 可以帮助选材，但角色真实经历需要 F 支撑。新增设定使用 P，不能混入已发生事实。

同一节点建议使用 2—5 个主要依据；只是控制复杂度，不是运行时标签数量限制。长 ID 放依据表，正文只放短标记。清洁展示版可另附，但必须同时交付标注版。

## 5. 写作粒度

主要单位是“一个局部处境、一次有意义的变化、一个接续边界”。

| 单位 | 建议粒度 | 写作边界 |
|---|---|---|
| 素材片段 | 1—3 句，约20—60字 | 一个外观、动作、感受或表达功能；独立可读 |
| 普通故事节点 | 约80—200字 | 写清当前处境，停在选择点；选择后的结果另写 |
| 重要剧情节点 | 按需扩展 | 可以较长，但不能越过尚未发生的选择 |
| 行动结果 | 1—3句 | 本次动作、反馈和已确认效果 |
| 完整事件 | 若干相连节点 | 单独列流程、分支、出口与结局；不要只交一篇长文 |

字数是编辑建议，不是格式限制。简单休息或购买无需强拆成多个节点。求助、回应、救援到达、脱困、治疗涉及不同事实，通常需要分别承载。

只有措辞、颜色或光泽不同，优先做片段变体。可用行动、进入条件、代价、结果或下一步不同，才另开分支或节点。

## 6. 战斗文字

敌我双方属性先列出：身份与形态、真实身体/材料、装备、生命与体力、相关战斗数值、已成立状态、可用行动和场地。未知写“未知”，模板未定义的资源写“未定义”，不能补零。

每次战斗反馈只交三列：

| 状态 | 行动 | 造成效果 |
|---|---|---|
| 本次实际起始状态及相关敌方意图 | 本次合法动作及敌方实际动作 | 本次已结算的命中、伤害、消耗、状态及胜败结果 |

不写长篇心理、比喻、对白和镜头描写。故事描述从遭遇节点或战后节点承载。

战斗稿必须读取实际回合结果，或明确标记“未模拟的路线设计”。不得编造命中、暴击、伤害、行动消耗或连续回合账目。输入不足时交待补清单，不凑一条看似实玩的日志。

本次代码核对的具体约束：体力≤19不允许进攻；进攻、防守、撤离和临时包扎还分别有费用与行动点检查。写作 AI 每次都应读取当前版本，不把这些数值当永久设定。

早前聊天中的“体力16仍连续进攻”样稿不符合当前门槛，不作为范例。也不能仅凭文案“黏性外层”就新增程序尚未记录的黏附状态。

## 7. 战斗外文字

- 遭遇：当前可见环境、在场者与正在进行的行为，停在可选择的入口。
- 探索：本次实际发现及其依据。未发现信息、隐藏答案和未到场者的知识不能提前泄露。
- 日常：动作方法、身体/工具/环境带来的差异和本次结果；简单行动保持简短。
- 交谈：对白与反应依据当前事务、性格和记忆。人物没在场、没被告知的事实，不自动知情。
- 任务：保留作者确认的关键事实与结局；接取、执行、回报和奖励分别对应真实进度。
- 身体变化：明确目标部位、原状态、转化阶段与能力影响。皮肤被覆盖不等于身体材料已置换；感受不能凭空授予能力。
- 战后：从已记录的战斗结果进入；逐步写敌方行为、我方回应、处境变化和脱离/后续路径。
- 结局：总结本次实际留下的状态、任务与关系结果，不补造长期影响。
- 系统/任务记录：直接说明条件、费用、结果与下一步，使用简短信息文字。

通常使用第二人称“你”。角色反应随已知经历变化；未知心理不要写成绝对事实。避免反复套用“你做出了选择”“按自己的节奏继续生活”等无具体进展的句子，也不要在剧情内解释引擎或素材格式。

## 8. 敌人倾向与可组合节点

设计时分开记录能力、目标、倾向、性格、资源、环境和当前状态。素材库存在某种偏好，不等于某个敌人拥有它；需有任务方确认的角色档案。

能力决定可执行范围，目标决定本场推进方向，倾向影响候选偏好，性格影响做法，环境与资源限制可行性。节点不满足硬条件时，倾向权重再高也不能选择。

普通敌人可以复用节点；首领、固定人物和关键任务可有专属节点。不要按每种敌人写完整重复故事，也不要把各敌人只替换名字后当成不同稿件。

变化至少应落实到行动、方法、阻碍、回应选项或结果之一。颜色、形容词变化只能算描写变体。

交付匹配建议时说明必需条件、排除条件、倾向影响、次数限制和结束条件。当前已实现`NarrativeProfile.tendencies`和加权阶段选择：先过滤真实条件，保留最高优先级，再按节点基础权重加上档案与节点倾向权重乘积抽选；已选节点随存档保存，不在查看时重抽。数值沿用现有包或明确委托，不擅自改规则。

规则字段与正文分开：`requiresTags/excludesTags`必须写`role+tagId`，`conditions`查询真实能力、身体、环境和资源；`setTags/unsetTags`只记录本次事实，不能伪造身体派生标签。`next`指同一类别的后续阶段，`null`结束。每节点1至4个选择，至少一个无条件、不扣资源的出口；访问上限1至3次，整段最多12步。每种类别保留无条件start回退。不要写一段包含所有未来选择和结局的长文。

涉及亲密互动时，成年资格、明确同意、偏好开关与内容分级分别检查。偏好和战败结果均不能替代同意；不编写由偏好自动触发非自愿性行为的流程。未知资格使用通用回退文本。

## 9. 统一交付模板

下列是编辑卡，不是 EventDef、ContentPack 或素材 JSON。卡片 ID 使用局部编辑编号，不占用正式工程命名空间。

```text
任务名称：
模式：existing-prose / runtime-nodes / proposed-nodes
工程基线：已读文件、读取日期；有提交号则记录，无则写未知
本次范围：
依据表：标记、真实ID/事实、来源、对象、审核与安装状态

角色/敌我属性：只列查实值；样稿假设单列
事件流程：入口 → 节点 → 分支 → 结局/退出

节点编号及用途：
对应已有事件/节点：无则明确“新提案”
进入事实与必需条件：
排除条件：
参与者与目标对象：
允许展开的事实：
本节点不能提前发生的事实：
matrix cell 的 assemblyRuleId：只引用独立规则，不内联拼装字段
独立 assembly-rules.json：规则ID、分级、校验、词池、普通回退
proseTemplate：按出现顺序列八类槽token，含key、bindTo、连接词及required
词条入槽表：ID、allowedSlots、poolIds、priority、审核、binding、前置及互斥
materialFluid 定词：挂前顺序、同实例检查、缺失与重复处理
prose：完整普通回退，保留依据标记；不是默认整段正文交稿
拼装成功预览及失败回退报告：包含T32/T34前后复核
选择表：选项｜适用条件｜本次效果｜下一节点
差异片段：变体依据｜替换范围｜是否影响后续
退出/失败/资源不足路径：
重复进入与记录要求：
待实现项：

交付末尾：来源清单、缺口清单、自检结果
```

existing-prose中的选择和效果只能抄录现有契约；正文扩写不能更改它们。runtime-nodes必须列出真实字段映射和来源，不能把已经支持的倾向与选择器误报为待实现。proposed-nodes中的新增能力要说明目标与前后变化，等待规则作者实现。数值来自工程或明确委托；不能自行编奖励或代价。

选择后的反馈文字同样按独立规则交模板、入槽词与普通回退，不能以“反馈”为名继续只交写死整段。下节既有接口范例只说明当前事实与结算边界；新的制作稿须按上述槽位格式交付。

## 10. 完整范例：当前外衣黏附节点

模式：existing-prose；对应已实现的组合故事节点`progression:node.defeat.coat`，类别`defeat`，阶段`assess`。来源：`content/adventure/pack.json`和`scripts/build-adventure-content.mjs`。

| 可见标记 | 正式依据 | 作用域与限制 |
|---|---|---|
| 【外衣黏附】 | progression:tag.coat.stuck | player；战败结算写入的本次事实，不证明身体黑胶化 |
| 【已检查处境】 | progression:tag.assessed | player；前一选项实际执行后写入 |
| 【已发出求助】 | progression:tag.signal | player；只有选择求助后才写入 |
| 抓握能力事实 | body.hasCapability(grasp,count:1) | player的真实BodyGraph，不从黏附Tag推断 |

进入条件：本段处于`assess`阶段；player拥有`progression:tag.coat.stuck`；player实际具备抓握能力。当前节点优先级5、基础权重10、最多访问1次。没有抓握能力时使用适用的其他节点；倾向不能绕过硬条件。

对应正文键：`progression:text.node.defeat.coat`。当前粒度示例：

> 外衣的下摆粘在低处【外衣黏附】，身体本身没有因此变成黑胶。你确认手边仍有可用的抓握部位，可以尝试松开外衣，或请求协助。

保留选择契约：

| 选择 | 条件 | 真实效果与本次事实 | next |
|---|---|---|---|
| 松开被牵住的外衣 | 抓握能力≥1 | 时间+15分钟；生命+5；移除player的coat.stuck | null |
| 发声请求协助 | 无额外条件 | 时间+5分钟；写入player的signal | help |
| 结束当前经历，回到安全位置 | 无条件 | 不扣资源，结束本次故事 | null |

选择后的结果键与正文同包保存。例如松开外衣的结果写“你松开外衣的牵扯，沿台阶回到安全位置。”这句话不能提前放进尚未执行选择的节点正文。求助只确认信号已经发出，救援到达留给`help`阶段。

扩写此节点不增加新能力、新道具或新奖励。增加另一种可行处置时使用runtime-nodes模式，列清它的条件、效果、后续和出口；需要现有契约之外的机制才列为proposed-nodes。旧`district:event.defeat.gel`仍是兼容内容，不应当作默认新流程的唯一入口。

## 11. 缺口与审核

查不到所需 tag/词条时，先尝试组合已有原子概念；仍不足则列：缺失名称、需要表达什么、已查来源、无法复用的理由、建议归类、受影响节点。不要为每种物种或物件创建“某某黑胶化”专条，也不要把“材质+器具+动作+结果”揉成一个不可复用词条。

必须检查：

1. 所有正式 ID 都在本次读取的来源中存在，且类型、定义、状态正确。
2. 每个关键事实有目标对象与证据；未知没有被补成确定值。
3. 正文可见标记都有依据表映射；主题、素材和编辑概念没有冒充状态。
4. 战斗只有状态、行动与效果；动作合法，数值来自输入或明确标记未模拟。
5. 故事停在当前节点；没有提前替玩家选择或完成后续结果。
6. 分支改变实际经历；同义换写未冒充新分支。
7. 本节点的进入、退出、资源不足、重复访问和接续范围清楚。
8. 真正超出现有契约的能力与效果已进入待实现清单；已实装的倾向、状态及选择器已按真实接口引用。
9. existing-prose 保留原事实、动作、效果和下一个节点；文本槽仍为 prose_only。
10. 来源、写作稿、规则提案与审核状态分别记录；不得自批 approved。

写作交付不需要谎称已通过游戏测试。只有实际运行验证后才能记录命令与结果；纯文稿完成只写“来源与叙事自检完成”。
