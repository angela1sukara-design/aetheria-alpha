# 两层格式与转换契约 v1.3

作者层由01与schemas定义；运行层由独立assembly-rules.json和tools/runtime/assembly.mjs定义。tools/authoring.mjs是可执行的**中性测试快照转换参考**，不是游戏适配器，不创建人物/物件/动作、不写批准记录、不修改游戏状态。

## 转换表

| 作者层 | 运行层 |
| --- | --- |
| binding.subjectType | 独立审稿计划指定逻辑bindingKey，从权威快照取subject+instanceId；类型必须匹配 |
| pendingFacts + review=hold | 保留待补列表，不进入运行候选 |
| draft、已核实语义前置 | 构造一次性approved运行测试副本；通过全部验收后才可另行持久审批，不能先改原稿 |
| qualifierPlan | 按顺序转换为对应token的prefixPools，仅poolId/required/separator；无plan则不挂定词 |
| proseTemplate与prose | 添加checks T32–T37及完整规则外壳，fallbackTier始终general |
| 文字池对应的tagIds/theme | 登记/制作分类；实际场景资格由requires与对象查询提供，不能冒充已实现Tag过滤 |
| 专门感官子池 | 保留子池，并按02的runtimeAlsoIn加入通道中性的父池；绑定和感官通道条件不变 |
| place.current / actor.name | 生成displayRef:{field:'name'}词条，读取同revision精确绑定的唯一displayValues记录 |
| exit.current | 从真实免费退出动作生成text/actionId；next=null、零条件/零效果/零Tag改动 |

text与displayRef二选一；动态名字不二次展开模板、不执行HTML/代码、不改姓或重抽。旧存档/固定人物保留其已保存名称。主体名称相同不代表同一实例。

## 审核与测试顺序

1. 作者层Schema、版本、ID、池/槽/主体、查询引用先校验；原稿保持draft/hold。
2. 整合方核实词义涉及的全部事实和真实查询；无法映射的保留hold。自然语言真实性必须人工核对，不能靠一个Tag或机器字段检查代替。
3. 制定独立审稿计划：entryId、当前稿件SHA-256、bindingKey、已核查semanticFacts与跨对象relatedBindings；不能让作者自批。修改稿件后摘要不符必须重审。
4. 从可信快照解析唯一实例及事实记录。事实既要对应登记查询，也要绑定正确主体/实例。跨对象包含/持有等关系另有明确证据；不把多个候选随便选一个。
5. 只在临时运行副本中用approved跑严格词条校验和真实拼装器，检查正常/失败/状态不变/名称绑定/预算/退出/存档复现；测试副本不改变原稿审批状态。
6. 全部通过再进入独立的持久审批/入仓事务。此事务及游戏运行适配器尚未实装；本包工具只输出fixture-only结果。

中性闭环用10中的人工构造快照及独立测试审稿计划。其facts使用现有拼装器接受的snapshot/engine-query来源枚举，但每条均标明synthetic测试来源，不是假称调用了游戏查询。09的productionAdapterImplemented均为false，禁止把演示快照拿去给真实玩家背书。

## 定词的完整约定

主名“水” + 定词“过滤” + separator="" → 过滤水。
主名“黄铜” + 定词“带细纹” + separator="的" → 带细纹的黄铜。

定词和主名同实例；body.material与部件sameAs。required=false且无合法定词时只输出主名，required=true则整段回退；主名不存在时不留孤立定词。相同定词池不能在同一主名上重复挂载，词条末尾不写“的”，防止“的的”。不同实例可有不同温度，exclusive不跨实例全局互斥。

## 实施边界

本包完成作者格式、普通中性样例及离线验收参考。ENG仍需在工程中实现真实查询/Tag资格/模板选择/文本包/UI/存档接入；先一个普通节点端到端验证再扩大。T32/T34复核与免费出口不可因回退绕过，本包不新增年龄字段。其他分级稿件不在本包制作范围；任何扩展也必须保留完整普通回退与真实资格检查。
