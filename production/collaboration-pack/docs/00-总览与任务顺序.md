# 通用展示文案协作包 v1.3

本包用于其他AI不能访问游戏工程时的结构化文案协作。只包含必要规范、任务、完整数据样例、Tag快照和离线验收工具，不含完整游戏源码。九类模板覆盖不代表九类玩法完成；出生、关系路线、独立任务/技能/修理等工程缺口不由文字冒充。

## 文件与用途

01是完整作者规范；02是唯一词池/主题/配额表；03是含draft和hold的真实格式示例；04说明发什么；05是按池分组的538个Tag参考；06是Tag提案协议；07是作者/运行两层转换契约；08是完整注册Tag快照及出处；09是事实目录及映射状态；10是中性测试闭环；11是实际验收结果。assembly-rules.json独立存放运行规则。schemas提供精确JSON Schema；tools提供无需第三方依赖的Node24离线检查。

任务卡保留A1/A2/A3、B1/B2/B3、D1/P0/T1。它们是文案任务号，与原ai.md中A区域/B分布/C服务/D性格/E关系模块无关。工程接入阶段统一叫ENG。

每张卡另有“独立发卡”全文版，已把所需规范、数据和样例合并在一个MD中；T1包含完整Tag快照。可以只把该完整文件发给不能访问工程的AI，不用目录/指纹代替内容。运行工具仍由整合方执行，写手无工具时诚实标手工预览。

## 顺序与放行条件

1. 先用P0小题评估手头可用的候选模型，不依赖某个固定模型名称或未经核验的价格推荐。P0产物不计正式完成。
2. A/B可并行，但各批共享本版规范；作者层先做少量稿，不先铺满17题材。未知语义事实保留hold。
3. T1有完整快照可并行提出建议，只有整合方有注册权；批准、依赖/指纹/参考表/覆盖/测试同步后，词条才可引用新ID。
4. D1在第一批之后做独立核查；结构/事实/对象/出口错误零容忍，10%阈值只用于人工文风问题。失败案例及预期结果已经放入tools/check.mjs和11。
5. 用07的明确测试整合计划跑作者稿→临时运行副本→真实离线拼装闭环；不得修改原稿为approved来骗过检查。本包已经提供中性fixture闭环，真实游戏ENG仍待仓库内实现。
6. ENG先接一个普通节点，验证真实绑定/查询/失败回退/同seed复现/存档重放，再放量。模板轮换、游戏Tag资格和持久审批不因离线示例而自动实现。

## 数量与报告

正式首批A1为三个大类各6–8，A2为五个大类各6–8，A3为08类6–8，共54–72模板。
B1五个MVP题材各40道具+25感官=325词；B2各30人物+40动作=350词；B3通用135词；共810词。02是唯一配额来源，第二批另列。hold计入收稿量，不能计入可试拼/可上线覆盖。

保留两份自动报告：业务来源/规则/任务阶段/接口缺口覆盖，以及文案模板/词池/主题/Tag覆盖。前者已由原工程脚本生成，无需手写数千格；后者在内容入库后生成，两者不能互相替代。缺口保留稳定ID，不因移进issue就宣布完成。

本包只生产general普通展示文案。其它分级保留独立通道，本次不做迁移；分级扩展须保持明确格式、资格校验与完整普通回退，不新增年龄属性。

## 版本纪律

本包所有规范、池表、示例、任务与作者specVersion统一1.3；08另记录注册快照的源提交/文件指纹。字段变更整包升版；旧1.0/1.2稿不得混收。每批独立batchId、revision和作者；共享格式/Tag/适配器由整合方串行修改，不让多个AI覆盖同一文件。

汇报严格区分“作者稿通过”“中性离线测试通过”“游戏已接入”。本包已做前两层中的示例检查，不宣称新玩法或全词库生产适配完成。
