# 通用规范 v1.3：作者层词条与模板

本包只生产普通展示文案数据，不能代替游戏功能、事件结果或存档实现。写手无需完整工程；整合方使用07转换契约和工具做离线核查。默认以本版规范、词池表、事实目录和完整样例为准，旧1.0/1.2交付先转换再审，不混收不同字段格式。

## 八槽与绑定

冻结 place / propEnv / bodyPart / senseMod / actionCore / materialFluid / opponentForm / exitChoice，不新增姓名、气味或定词槽。词条一槽一制作池；模板可重复出现同一种槽，但每个key唯一。place.current、actor.name、exit.current由适配器填充，作者不交这些词。姓名读取已保存的精确对象快照，不重新拼姓/名、随机改名或由正文推定家族。

02列出所有制作池、主体类型、角色与逻辑绑定键。逻辑键place/actor/part/prop/material/sense/exit不是真实ID；整合时必须绑定到唯一实际实例。part的subject是部件所有者、instanceId是部件实例，不能将不同部件的材质混用。

## 词条完整字段

每条按schemas/word.schema.json提交：id、text、allowedSlots、poolIds、priority、review、status、role、binding、requires、pendingFacts、excludes、exclusive、contentTier、tagIds。不是“12字段”，不省略空数组。

- id用word开头的小写稳定ID；text为可入槽短语，通常1–40字，必要时最长80字；不要用长从句逃避槽位约束。动作池可用动词短语，其他池以匹配语法的短语为准。
- review只允许draft或hold。draft是字段、已冻结查询引用已自检的稿，不代表事实在当前场景成立、更不代表批准。hold必须在pendingFacts中列出尚未映射的语义前置；不得猜造事实名或删条件硬交。
- draft至少有一个事实前置、pendingFacts为空；hold可以没有requires，但pendingFacts不得为空。status为active/inactive，inactive不参与试拼。
- binding只写subjectType；作者不写subject/instanceId。requires只能用09登记的事实键，eq/gte/lte/exists四种比较。exists没有value；其他操作必须提供对应类型的value。未知查询走hold，已支持查询在某次场景未知/不成立时正常不入候选。
- exclusive始终是[{group,value}]数组。同一主体的同一实例同组异值冲突；不同实例的温度不同不冲突。excludes为稳定词条ID列表，任一方向声明均生效；交付时缺失的目标ID须在说明中列为外部依赖，不拼写不存在的ID。
- qualifier仅用于materialFluid，不带末尾“的”；连接符在模板qualifierPlan声明。
- contentTier在本包固定general；tagIds可为空，只用05或08中已登记且active的canonical ID。Tag登记不证明天气、姿态、道具、能力或意愿。
- 编辑备注写交付说明或批次notes，不往词条塞note/notes/weight/效果/代码字段。

09中的查询映射目前只在中性演示快照中可复现，生产游戏适配器尚未接入。使用这些键的draft最多证明作者层查询引用合法，不能计为已上线覆盖；其他事实先hold。未来生产查询加入09时须说明值类型、实例范围、真实来源和已实现状态。

## 选择机制与多样性

当前离线拼装器按priority降序，同优先级按seed+规则ID+槽key+词条ID的稳定散列排序，最后ID兜底；每槽取前4候选，最多64次有限搜索，上限配置8/128。没有weight字段，没有概率加权，也不保证所有低优先级候选最终出场。

可互换的普通词建议同档500，便于同seed稳定、换seed变化；不强迫每批分带。专用词若应覆盖通用词，采用较高priority且真实条件严格成立，通用回退词放较低档。给低档词加条件不会让无条件高档词消失。优先级不能代替资格；tagIds也不能代替事实前置。模板轮换需整合方另做确定性选择和存档复现，现有assembleProse只执行指定规则。

## 模板完整字段

按schemas/template.schema.json交id/domain/mode/contentTier/fallbackTier/proseTemplate/qualifierPlan/prose。九类domain为01–09。mode为prose；contentTier及fallbackTier均为general。

每个token含key/slot/poolId/bindTo/required/prefix/suffix，可用sameAs、subjectAs。sameAs要求主体及实例完全相同；subjectAs只要求同一主体。部件属于人物需subjectAs，材质属于该部件需sameAs；容器包含材料的关系需明确事实，不能用sameAs冒充。

prefix/suffix只用不含未验证状态的连接文字和标点。不得写“角落里”“袖口”“比昨天不同”“还没散去”“比记忆中更小”等常量。感官通用池只配“你察觉到”等通道中性的骨架；“空气里飘着”只能用于smell专池，不用于声音、光线、温度或触感。

qualifierPlan是作者层挂前意图，不是运行prefixPools。每项{key,poolId,required,separator}指定材料token；顺序即挂前顺序。body.material只配body.material.qualifier，material.current只配material.qualifier；必须绑定同一实例。最多两组，禁止同一key重复挂同池。separator为空或“的”；没有plan就不挂定词，整合者不得自行猜。07负责机械转换。

每条模板必须有required=true的exitChoice槽。可选槽无词时连连接文字/标点一起删除。prose为完整普通回退，建议“你可以结束观察，继续自己的安排。”；不声称已离开、已完成动作、无人有事或没有变化。回退不能凭空创建按钮，适配器未提供真实免费出口时应blocked。

## 交付与自检

使用schemas/delivery.schema.json，顶层format/specVersion/task/theme/author/batchId/revision/entries/handPreviews/suggestedTags，notes可选。specVersion固定1.3，主题用02的17项或generic。任务卡要求的配额以02的quotas为准，hold数量与可试拼数量分开，别把hold包装成已完成可用覆盖。

每条模板至少2条预览，每批至少3条；P0仅需2条。handPreviews是对象，含templateId、entryIds、fixtureId、seed、revision、mode、text、evidenceStatus。手工填写用manual/hypothetical-only；实际运行参考拼装器并附复跑记录，才能用reference-assembler/fixture-verified。本包03的示例由真实离线工具生成并测试，所以使用后者，仍不表示游戏接入。未有真实上下文时说明假设，不能宣称已复现。人工轮换低档词只能用于语感检查，不伪称引擎自然会选中。

提交前检查：Schema与版本、ID冲突、词池/槽/主体、事实来源与hold、同实例互斥、连接语法、定词挂前、动态名称、真实免费出口、完整普通回退。结构/串线/虚构事实/分级错误零容忍；文字画面感由人工审核，机器不能从自然语言自动证明事实完整。
