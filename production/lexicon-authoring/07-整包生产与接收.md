# 整包生产与接收

整包是默认委派方式：一次交给一个AI全部10700条，或分给少数AI各一个大类。内部编号不改变，不要求用户逐批操作。写作AI需连续完成本范围所有内部任务，按能力写入文件并打包，最终交一次结果。

## 整理者操作

1. 一次登记：“npm run lexicon -- assign-scope all ai-main”。若分开委派，分别登记npc/ai-npc、body/ai-body、world/ai-world、daily/ai-daily、text/ai-text。领取有冲突会整项拒绝，不会改写其他AI的批次。
2. AI返回的压缩包应包含lexicon-delivery.json与production-report.md。解压后运行“npm run lexicon -- validate-delivery 路径/lexicon-delivery.json”。不运行包内附加脚本。
3. “npm run lexicon -- import-delivery 路径/lexicon-delivery.json”一次收录本范围。按既有流程后续审定，游戏接入另做。

## 格式

整包顶层只含format=aetheria-lexicon-delivery、schemaVersion=1、scope及batches。scope可以是all或五个大类代码。batches是已有完整批次对象的数组，格式和每条稳定ID完全沿用batch.schema.json，外层结构见delivery.schema.json。

all必须覆盖214个内部批次、10700条。其他scope必须覆盖本大类的全部首期批次；不能把缺失范围当作完整交付。每批source里的producer应与范围领取一致，model如实记录，theme仍取production-plan.json对应主题。整包文件最多32 MiB。

完整性、批号归属、来源、最后一批格式以及全库精确重复先全部检查，预检任一失败不会收录任何词条。近似重复仍只提示编辑复核。已收录内容不覆盖，完全相同的整包再次导入是无操作。写盘采用逐文件原子写入；异常中断后可重复导入同一个包补齐并重建索引，不宣称跨214个文件具有数据库事务能力。

## 无法一次完成时

写作AI应尽量连续完成，并在确实受环境限制时保存实际完成量、完整文件和缺失批号，报告如实标为部分成果。完整性校验会拒绝把部分成果当作整包；整理者可保存已完成文件并使用原单批工具收录，或让AI从缺失位置接续。用户无需每50条确认。一次委派不保证任意模型能在一条消息里输出全部内容。

两种方式共享同一素材格式和来源记录，不改变规则、身体、NPC或事件系统。
