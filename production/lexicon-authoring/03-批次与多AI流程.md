# 多AI生产与整理

所有命令在工程根目录运行，需要Node.js 24或更高版本；随工程提供的依赖足够，不调用AI API。负责人统一操作词库，AI只交付文件。离线分发ZIP里的任务也能直接使用，不要求写作AI访问工程。

## 第一次派发

1. 查看production-plan.json或management/index.json中的未领取批次。用“npm run lexicon -- assign npc-trait.b0001 claude-a”登记领取，其他AI领取不同批次。
2. 把tasks/npc-trait/b0001.md全文发给AI，并告知producer必须填写claude-a。这是独立完整指令，无需另外给引擎源码。
3. 将返回JSON保存到inbox/npc-trait.b0001.json。对同一词库的后续AI，再提供已收录名称和短摘要，减少跨批雷同；不要发送未公开剧情源码。
4. “npm run lexicon -- validate production/lexicon-authoring/inbox/npc-trait.b0001.json”检查结构、本批精确重复和近似提示。validate成功只表示结构合法；仍须阅读报告。
5. “npm run lexicon -- import production/lexicon-authoring/inbox/npc-trait.b0001.json”合并收录。导入还核对任务数量、主题、领取人，检查与全部已收录素材的精确重复。通过后进入collections，状态为unreviewed。

## 去重与审稿

精确重复（忽略Unicode兼容形式、大小写、标点和空白）拒绝导入整批，不会悄悄删条。返回AI修改重复项、保留原ID并补足批量后再提交。同名不同描述、字面近似仅提示，不自动合并。近似检索按同类字组建立候选，存在漏检，不能识别所有同义改写。错字、视角、原创性、具体用途与语义多样性仍需编辑或另一AI审稿。

“npm run lexicon -- duplicates”生成全库重复报告。审稿使用examples/review.json作为格式参考，将decisions改为实际已收录ID，设置approved、hold或rejected并写明审稿意见；由整理者执行“npm run lexicon -- review 审稿文件.json”。AI交付正文不能自带approved字段。被搁置或拒绝的内容仍保留来源，且不会进入已审定导出；不自动改号或删除。

已收录批次不可覆盖。相同内容再次导入是无操作；修改已收录文件会拒绝。问题条目标记hold/rejected，新修订另开批次；原始ID与来源保留。若保留项与重复项需二次拆分，先在正式导入前整理，不以覆盖旧文件解决。

## 扩充与交换

- “npm run lexicon -- extend npc-trait gemini-b '夜班手艺人的不同处事风格'”分配该分类下一空号并生成outbox中的独立任务。标准仍为50条，不复用旧号。
- “npm run lexicon -- index”重建已完成索引与统计，包含首期和扩充任务。
- “npm run lexicon -- export production/lexicon-authoring/outbox/reviewed-v1.json”导出已审定素材及来源。这是纯素材交换文件，不能直接作为游戏包加载。
- 多台电脑统一交付给一个整理者；同一词库不要各自从b0001开始分配。异地分发前先集中领取批号，导入后提交Git同步。

文件锁避免两个本地整理进程同时写入；领取/收录失败后查看错误，不重复派号。若进程被强制终止留下management/.lock，确认没有整理进程运行后再移除该空锁目录，并运行index核对。index是可重建派生文件，collections才是原始收录依据。批次、审稿与索引使用单文件原子写入；系统中断时运行index恢复索引，不宣称跨多个文件具有数据库事务能力。
