# 词条与规则用途

这些是编辑层元数据，不会单独解锁动作、改变关系或赋予身体能力。现有 conditions、身体查询和事务执行仍是运行依据；规则模板编译器尚未实现。

| 字段 | 含义 |
| --- | --- |
| family / usage | 建议接入的规则类别与用途，并非现成规则 ID |
| allowedSubjectKinds | 允许绑定的编辑对象类别，不是可直接传给 EntityRef 的值 |
| requiredBindings | 必须补齐的主体、参照对象或互动场景范围 |
| value | 值类型与单位；default=null 表示资料未提供实际测量值 |
| sourceOfTruth | 运行时必须读取的权威事实来源 |
| missingValue | 缺失为 unknown，不把未知自动当作通过 |
| runtimeExecutable / effectsAllowed | 均为 false，不允许从这份资料执行效果 |

长度、厚度、净空等 20 个量纲使用显式单位；没有默认数值，不根据“狭窄”自动填入门宽。弹性、导电性等物性仅标注为参数维度，其具体量表需要单独定义，不把“出现该词”视为对象具备该属性。

空间关系需要 subjectId 和 referenceSubjectId。身体尺寸需要绑定同一个部位实例；多个角色各自查询，不能把全场标签混成一套。

情绪是当前状态；性格和习惯是选择倾向；目标是愿望；经历和互动同意是有来源的事实。兴趣不授予技能，职业不授予许可，随和不代替同意。邀约、接触、暂停、继续需要检查本次范围、资源和兼容性。

编辑示例（不是可执行脚本）：

1. 搬运：绑定行动者与具体物品，查询其质量、可握持结构和当前资源，再由已有事务结算。
2. 通道：绑定具体身体部位与通道，对照真实尺寸、姿态和净空；尺寸缺失时不能仅凭“宽阔”放行。
3. 日常对话：当前情绪决定表达变体；已记录经历决定可提及事实，不从词条定义创建新记忆。
4. 互动恢复：读取实际场景、参与者与本次同意，重新校验身体和接触资源，不依据“信任”跳过检查。

导入文字：node scripts/lexicon/cli.mjs validate-v2 <批次文件>。校验只证明结构、分级和字典引用符合要求；审稿与安装需走已有内容流水线。文字批次无奖励、效果或状态字段，编辑 ID 不硬塞进运行字典。

同名候选仅排除重复添加，原有概念或素材保留；某些同名词可能处于不同语义或作用域，必须阅读 label-collisions.json 再决定是否人工关联。
