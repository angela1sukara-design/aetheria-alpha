## 仅有编辑接口与建议

`rule-hints.json` 是供后续规则开发使用的旁路资料：规则类别、意图、主体绑定、单位、事实来源与未知值策略。它明确标注 `runtimeExecutable=false`、`effectsAllowed=false`，不能直接传入条件执行器。

交换批次只提供文字。编辑概念未注册为运行 `TagDef`，所以批次 `tags` 留空；未修改引擎以强行接受编辑 ID。安装仍需走既有审稿及内容流水线。

## 读取和重建

从 `production/tag-deliveries/2026-10-12/general-expansion-v2/README.md` 开始。人工阅读用 `新增通用词条.md`；只取新增用 `common-additions.json`；完整主表用 `entries.jsonl`；规则用途见 `规则用途说明.md`。

在现有工程根目录运行：

```text
node scripts/lexicon/build-general-expansion-v2.mjs
node --test tests/general-expansion-v2.test.ts
npm test
npm run typecheck
node scripts/lexicon/package-general-expansion-v2.mjs
```

需要现有工程、Node.js 24+ 和现有依赖。补充 ZIP 包含本轮资料、生成及打包脚本、测试、验证结果和说明，不是完整游戏源码包，也不是可直接运行的 HTML 游戏。

ZIP 内及旁边的 package manifest 记录逐文件哈希；打包时解压校验每个成员，不把前一轮 ZIP 覆盖掉。后续继续增补应另开批次，保留已发布 ID。

下一轮建议补充领域覆盖用例，优先落实搬运、通行、装备适配、工作、对话和互动恢复的可复用规则模板，再对旧拆分待审队列进行有来源的复核。
