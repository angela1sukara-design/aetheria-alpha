# 词条交回后的接入方式

用户可以继续使用已交付的 `Lexicon-Authoring-v0.2.zip`，一次让外部AI生产大部分素材，最后交回完整压缩包。无需让写作AI设计NPC剧情、权重、互斥、事件效果或身体机制，也无需改变现有词条格式。

本轮没有导入尚未交付的词条，也没有把默认参考模板当成海量词库。生成器已补好以下文本使用位置：

| 基础素材方向 | 将来适配的字段 | 处理方式 |
| --- | --- | --- |
| 姓名、称呼、性格 | ResidentTemplate.names / personality、对白 | 按语义选取已审核素材，再绑定到稳定原型 |
| 职业与日常表现 | profession、dialogue.intro / repeat / help | 先匹配已实现职业；只有文本的职业可以先留在库中 |
| 地点、建筑、经济环境细节 | place.names / description / economy | 文本可以扩充，玩法用途仍由service和独立规则决定 |
| 天气、声音、光线、街区细节 | environment.description / place.ambience | 由环境和时段选择，选定文本随世界快照保存 |
| 工作、进食、休息、观察动作 | activity.label / description | 只替换文字，时间、成本、收益与身体条件另行审核 |
| 开场、回应、重复见面与协助 | dialogue三个字段及未来普通文本适配 | 只描述真实关系阶段与已成立的事实 |
| 身体与外观 | 原型外观和基于实际BodyGraph的描述 | 不根据素材文字凭空添加器官、能力或TF |
| 当前尚无玩法的内容 | 独立基础词库 | 照常收录，标记未使用，等待对应机制 |

接入顺序：校验交付格式→去重与来源登记→审核并收录素材→维护“已收录/已使用”分账→按独立规则制作内容/参考包→生成未来新世界→运行复现与存档测试。用户不需要参与逐个NPC的剧情设计。

基础词库中仍然不放随机权重、互斥规则、效果脚本或行动数值。未来组合适配层负责把素材映射到受校验的内容字段；不能把词库JSON直接当成ReferencePack或ContentPack加载。

新词条只影响之后生成的世界。旧世界保留原名字、身体、关系、记忆与描述快照，不因为素材库变多而重抽。与真实身体或事件事实矛盾的文本应暂缓使用，不能只因关键词相近就自动拼接。

此轮提供明确的接入字段和边界，尚未自动将整套词库编译成游戏规则。待实际素材交付后，再依据内容和审核结果实施适配与样本验证。
