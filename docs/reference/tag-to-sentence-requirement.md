## 0. 先读这一段

玩家、NPC、怪物身上的标签是意思。程序用固定句式把这些意思译成一句普通人能读完的中文。换标签就换句中的对应成分。不要为每一种标签组合另写一篇。

「类似翻译器」在这里只有一个意思：结构化事实进去，合乎语法的句子出来，用词表和句式完成，同一次事实永远得到同一句。它不是调用大模型，不是机器翻译 API，不是把每个标签译成一整句再接起来，也不是事先写好的段落对照表。

`sandbox/five-room/` 里现在这两版正文都不符合本文件：

- 性格一句、关系一句、地点一句接在一起。
- 每种性格 × 每种关系各写一整段，标签只负责选段。

## 1. 词

| 词 | 含义 |
| --- | --- |
| 事实 | 这一屏已经成立的状态。名字、性格、关系、覆层、部位、地点、怪物、这一拍发生的接触。事实由玩法结算写入，造句时只读。 |
| 标签 | 事实的稳定 ID，例如 `forthright`、`colleague`、`coat.slime`。标签不是句子。 |
| 成分 | 一个标签在某一句式里贡献的短语。成分短于一句，自身不带句号。 |
| 角色 | 成分在句式里的职务：谁、方式、看见的东西、做的动作、接触的部位。同一标签在不同句式里可以有不同角色，不能因此变成一整句。 |
| 句式 | 有序的槽。槽上写明角色、要不要、前面的连接字、后面的连接字。 |
| 词表 | 标签 + 句式 + 角色 → 成分。词表是数据。句式不知道「直率」的中文，只知道把 `manner` 槽放在哪里。 |
| 翻译 | 用当前事实选出成分，填进句式，删掉没有事实的槽及其连接字，得到一句正文。 |
| 一屏 | 玩家当前看见的正文。一屏用一句式译出。结算后的下一屏可以换一句式。不要把上一屏的句子和这一屏的句子粘在同一段里。 |

## 2. 翻译步骤

对一屏只做这些事，顺序不能换。

1. 读取这一屏的事实。缺的事实保持未知。未知不能填成猜测、怪物名字或打法。
2. 选定这一屏的一句式。进门、问话、交锋、战败、留下、洗净，各用各的句式。
3. 每个槽按角色从词表取成分。一个槽最多一个成分。没有合格成分的槽整段删除，连同它的 `prefix` 和 `suffix`。
4. 同一角色有多件事实时，在该槽内部用「和」连成一个名词短语，仍然只占一个槽。例如黏液和束痕都是「看见的东西」。
5. 按槽的数组顺序拼字。拼完必须是通顺的一句：有主语，有一个主动作，读出来不用在心里补「这是性格」「这是关系」。
6. 同一事实再次翻译，得到同一个字符串。种子只负责掷事实，不负责在造句时再随机换词。

正文不写状态。句子里出现「拍了一下」不会扣钱、加覆层或推进战斗。那些只发生在选择被提交的时候。

## 3. 词表条目长什么样

一条词表数据只有短语。下面是形状示例，不是要求照抄的文案。

```json
{
  "id": "manner.forthright.enter",
  "tag": "forthright",
  "frame": "enter",
  "role": "manner",
  "text": "看着"
}
```

```json
{
  "id": "act.colleague.haven",
  "tag": "colleague",
  "frame": "enter",
  "role": "act",
  "place": "haven",
  "text": "手在床沿空出的位置上拍了一下"
}
```

```json
{
  "id": "percept.coat.slime",
  "tag": "coat.slime",
  "frame": "enter",
  "role": "percept",
  "text": "小腿上还在滴的黏液"
}
```

下面这种不是词条，不能入库：

```json
{ "tag": "forthright", "text": "对方看着你，不绕弯。" }
```

```json
{ "tag": "colleague", "text": "你被当成还会一起干活的人。" }
```

拒收原因：它们各自是完整的一句说明，翻译时只能再并列，读起来像清单。

## 4. 进门句式（规范例）

落脚点或工坊进门只用这一句式。地点差别写在 `act` 的词条里（床沿 / 柜台），不另起一句「灯下有床，也有水」或「柜台上摆着护具」。

槽顺序：

| 顺序 | 角色 | 必填 | 前 | 后 | 空事实时 |
| --- | --- | --- | --- | --- | --- |
| 1 | name | 是 |  |  | 不能空 |
| 2 | manner | 是 |  |  | 不能空 |
| 3 | object | 是 |  |  | 没有身体事实时，这个槽固定是「你」，不占标签 |
| 4 | act | 是 | ， | 。 | 不能空 |

`object` 有身体事实时，仍是一个槽：先写「你」，再写身体短语。多处身体在这个短语内部用「和」连接。逗号属于 `act` 的前缀，因为动作槽必填，所以逗号一直在，不会跟着身体事实一起被删掉。

`manner` 只提供动词或方式短语，例如「看着」。它不包含「你」，也不包含逗号。每个 `manner` 词条都必须能直接接在名字后面、再接 `object`，使「名字 + manner + object」本身是合法的动宾。不能填「不绕弯」「目光躲开」这种接上宾语就破句的短语。羞怯若要换成别的看法，词条写成能带宾语的说法，例如「侧过脸看」，而不是另起一句。

事实：老闸、直率、同事、落脚点、身上干净。

译出：

> 老闸看着你，手在床沿空出的位置上拍了一下。

事实改为小腿还有黏液，同一句式译出：

> 老闸看着你小腿上还在滴的黏液，手在床沿空出的位置上拍了一下。

事实改为黏液和束痕都在，仍是一句：

> 老闸看着你小腿上还在滴的黏液和手腕上的束痕，手在床沿空出的位置上拍了一下。

把性格换成羞怯，只换 `manner` 对应的成分，`act` 仍是同事那一条。不要整段重写。

下面这一句算失败，即使每个分句单独读得通：

> 落脚点的灯还亮着。老闸在这里。对方看着你，不绕弯。你被当成还会一起干活的人。灯下有床，也有水。

失败点：五个标签各成一句。

下面这一版也算失败：文件里有 6 种性格 × 5 种关系共 30 段写好的进门正文，运行时按标签挑一段。段落写得再顺，标签也没有参与造句。

## 5. 其他屏用同一条规则

每屏一句式。句式可以不同，规则相同：标签出成分，空槽连连接字删除，多件同类事实在槽内用「和」连接。

| 屏 | 句式要译出的意思 | 禁止出现的句子 |
| --- | --- | --- |
| 问话 | 这个人用他的性格方式说出允许公开的事实 | 怪物名、弱点、打哪里、以及「名字和打法都没讲」这种对玩家解释规则的话 |
| 交锋 | 什么东西接触到你身上的哪里，距离还有多近 | 「你可以硬拼或撤退」 |
| 战败 | 你现在被压在什么里面，接触停在哪 | 「你可以挣回落脚点，也可以留下」 |
| 留下 | 变化进行到哪一寸，对方停在哪里等你 | 「点头之后就洗不掉」「两条路都会封上」 |
| 洗净 | 水或手巾正在擦掉覆层 | 「长出来的部位还在」这种说明；部位还在就让它出现在句子的物件里 |
| 恢复人形 | 多出来的轮廓收回去 | 把耳朵、手、手臂、尾巴列成清单，除非这些部位确实都在事实里，并且列在同一个名词短语中 |
| 赢、买、交货、记住打法 | 眼前物件的变化（门关上、零件在掌心、盐停在那个高度） | 「你赢了。」「你记住了：某句打法。」 |

第二人称、现在时。写你眼前有什么、对方正在做什么、危险离你多近。句子停在对方的动作上，让按钮去做决定。按钮文字不是翻译器的输出。

## 6. 按钮

按钮是玩家提交的行动，文案手写，短于一句，不以「。」结尾。

允许的形状：`从泥里把腿挣出来`、`挣回落脚点`、`把嘴唇合上`。

禁止这些按钮，包括同义改写：观察、确认细节、饮水机、查看周围，以及任何只展示说明、不改变事实的按钮。做不到的功能不出现。缺资源时可以出现带代价的行动；不能用灰掉的说明按钮代替。

## 7. 五间房在提供哪些事实

这一节是翻译器允许读取的玩法事实。数字（价格、体力）不是本需求，现有沙盒里的数只是试玩用的，可以改，但不能靠改数来代替造句。

一局五间，不是四间，也不是四十五间。「45个房间」是笔误。

| 房间 | 事实 |
| --- | --- |
| 落脚点 | 安全。可睡、可问前方、可洗净覆层、可恢复人形、可去工坊。 |
| 工坊 | 可问更里面、可买护具、可接并交付零件、可买或因性癖免掉情报、可进入暗渠。 |
| 暗渠 | 第一间高危。泥会吞脚。里面的怪物二选一。 |
| 泵站 | 第二间高危。通过后才站得住。最里面有首领门。 |
| 首领房 | 一扇门后面的一场战斗，不另算第六个可游逛房间。 |

玩家标签、看管人标签、店主标签每次开局掷一次。怪物从各自的池里掷一次。同一种子得到同一组事实。

玩家可被翻译的标签：身体材料（有机 / 机械）、一项身体能力（抓握、行走、听觉、平衡、尾部抓握）、一项性癖。NPC 可被翻译的标签：性格、关系、性癖、材料。性格和关系不提供身体能力，也不提供同意。

性格池：高傲矜持、羞怯敏感、直率豪爽、精明务实、虔诚克制、狡黠活泼。关系池：同事、邻居、熟人、旧怨、人情债。

性癖对上店主，或对上正在打的那只怪物，情报不花钱。只对上看管人，不够。

问话只能使用模糊事实：前方潮、会吞脚、有的贴上来、有的往手腕上收、有的成群、有的会追出门、最里面有门。问话词表不得含这些字面：史莱姆、盐、藤、主根、虫、茧、狼、鼻梁、涎、黑胶、守卫、口令。买下情报之后的那一屏可以用对应打法的成分，因为事实已经从「未知」变成「已知」。

侧栏在遇见之前不写出怪物名字。

## 8. 战斗、覆层、留下

战斗是三拍选择，不是把体力扣到零再播一段战败。每一拍一句式。

怪物至少这些，只许按各自标签选成分，不许共用一篇「糊上来」：

| 怪物 | 接触方式 | 覆层 | 留下之后多出来的部位 |
| --- | --- | --- | --- |
| 沼史莱姆 | 爬、糊、打滑 | 黏液 | 史莱姆手 |
| 暗渠藤蔓 | 勒手腕 | 束痕 | 一条藤肢 |
| 虫巢爬行者 | 围腰、缠丝 | 结茧 | 触角 |
| 兽径涎狼 | 按住、咬颈、追出门 | 颈侧牙印 | 狼耳和一条有机长尾 |
| 黑胶守卫 | 封嘴、等你自己合上 | 唇上的膜 | 黑胶手 |

涎狼是野兽。它不让玩家打滑穿过泥，不把人变成黏液或胶。史莱姆手或黏液覆层才能滑过暗渠。听见狼（狼耳或听觉能力）可以改变交锋句式里的「先听见」成分，并可以改变撤退代价；这句话仍然是翻译，不是在正文里解释规则。

覆层和部位是两种事实：

- 战败写入覆层。洗净只删覆层。
- 「留下」才写入部位。洗净不删部位。恢复人形只删部位。
- 赢不写入覆层。若上一拍已经扛下并写入覆层，后来拼赢，覆层还在。
- 兽径涎狼留下时同时写狼耳和长尾，这是一条事实的两个部位，翻译进同一个名词短语。

成人内容默认关。关掉时没有「留下」按钮，战败仍能回落脚点，循环仍能走完。打开后，「留下」才逐拍把部位译出来。首领的留下是封口的过程，用同一条翻译规则，不能只显示一个组合标签的名字。

赢和输都要能回到下一天。睡觉恢复体力，当天的通关清掉，已知情报、护具、覆层和部位保留。

## 9. 这些做法算做错

1. 把「拼出来的文太烂」理解成「禁止拼」。要改的是拼法，不是改成手写全文。
2. 为性格 × 关系 × 身体 × 地点预写整段，运行时挑选。这是对照表。
3. 一个标签产出一个完整句，再把这些句子依次连接。
4. 运行时调用大模型、翻译 API 或自由续写来生成这一屏。
5. 把本需求接到原工程的 `ActionExecutor`、内容包、`prose-assembly` 或世界生成器。可以沿用已有的名字和标签含义。旧的八槽规范只说明「有序槽 + 词条 + 空槽连连接字删除」这件事已经定过；不要去改那套生成物，也不要把它的观察正文搬进五间房。
6. 正文解释按钮、数值或胜负判定。包括「你可以……」「洗不掉」「点头之后就会」「你赢了」「你记住了」。
7. 问话或侧栏提前说出尚未遇见的怪物、弱点或隐藏词。
8. 用性格、职业或关系代替身体能力。滑泥只看黏液覆层或史莱姆手。
9. 把覆层和部位写成同一种变化，或让洗净把部位洗掉。
10. 成人内容默认打开，或关闭后循环走不完。
11. 增加观察、确认、四处看看一类不改变事实的按钮。
12. 造句消耗随机数，或改写权威状态。
13. 空槽删了词、留下连接字，出现「看着，，」或「带着。」。
14. 多处身体事实各写一句。它们必须在同一个「看见的东西」槽里。
15. 把按钮翻译成带句号的说明句。

## 10. 怎样验收

用事实表验收，不用主观「好不好看」验收。下面每一条都要能自动检查。

1. 同一事实译两次，字符串相同。
2. 只改性格标签，进门句里只有 `manner` 成分变化，名字、动作短语和标点结构还在。
3. 去掉全部身体事实，含身体的那一段和它的连接字消失，剩下的句子仍然通顺，没有双逗号、没有悬空的「你」。
4. 同时有黏液和束痕时，两词出现在同一句里，并且用「和」连接，整屏句号只有一个。
5. 问话字符串不含第 7 节列出的隐藏词。
6. 词表里不存在「句号结尾、且可独立成句」的性格条目或关系条目。
7. 源码里不存在按性格 × 关系索引的整段正文表。允许存在按角色索引的短语表。
8. 关掉成人内容，战败选项里没有留下，回落脚点后循环还能继续。
9. 战败只增加覆层；留下才改变部位；洗净之后覆层空、部位还在；恢复人形之后部位回到人形。
10. 任意一屏的按钮不以「。」结尾，文案不含「观察」「确认细节」「饮水机」「查看周围」。

第 4 节的三句示例用来核对句式形状。把示例句子写死成唯一输出，并且换一个性格仍然输出这三句，验收失败。

## 11. 不在这份需求里

- 不重做原游戏的规则编译器。
- 不把八槽观察模板接进五间房。
- 不规定护具、情报、委托的具体价格和体力公式。
- 不要求每一屏文学上互不重复。要求语法成立、成分来自标签、同事实同句。
