# 赛博主线接入：站上顶点

> 2026-10-13：本文保留原赛博示例与底层任务协议。默认生成入口已改用[17 种世界 Tag 与任务配置](world-profiles.md)。下文种子页面与默认入口描述、七条支线数量为原实现记录；当前验收使用 `tests/world-profiles-browser.mjs`。

更新：2026-10-12。用户已确认接入内容绑定、五类轻量关系与任务记忆、Journal 三项功能。

## 玩家入口

在游戏的“世界”页生成新街区，即可在“任务”页看到首富与军阀两条路线。按日志中的具体地点，在当地选择“主线 · 阶段名”。也可直接打开 `dist/WorldGenerator-Seed-7.html` 或 `dist/WorldGenerator-Seed-42.html` 离线试玩。

每条路线四阶段，全部通向“站上顶点”。两条路线可以同时准备，首次完成任一终局后关闭全部主线入口，支线和普通生活仍可继续。每个阶段至少两种实际做法，有免费替代路线和无条件暂缓出口。退出事件不算完成，重进不会丢失阶段。

首富路线通过最大财团的控股与交割完成；军阀路线通过哨站、补给和最高指挥授权完成。本版军阀路线是选择式的武力统治叙事，不包含自动派系战争或军队模拟。

七条支线分为两条主线相关、三条人物支线、两条当地短篇。相关支线仅开放额外选项，不是主线前置；人物支线和短篇均在当地通过实际选择完成。小规模世界没有符合关系与日程的居民时可略过相应人物支线，主线仍完整。

## 文件与制作流程

| 文件 | 职责 |
| --- | --- |
| `production/quest-authoring/cyber-apex/quest-tree.json` | 用户指定结构的作者源文件：阶段、地点类型、旗标、Journal 和关系规则 |
| `production/quest-authoring/cyber-apex/execution.json` | 明确的玩家正文、按钮、费用、完成行为与记忆；不从自然语言猜测效果 |
| `scripts/build-quest-content.mjs` | 离线校验与打包，记录作者源文件哈希 |
| `content/generation/cyber-apex.json` | 随新世界加载的已打包任务模板 |
| `src/content/quest-schema.ts` | 任务制作格式校验 |
| `src/world/quests.ts` | 地点、居民、关系绑定与 ContentPack 编译 |
| `src/world/quest-validation.ts` | 任务世界快照与 Journal 引用校验 |
| `src/engine/resident-quests.ts` | 动态居民在场、关系与亲历记忆 |

修改作者数据后运行 `npm run quests:build`。`npm run build` 也会打包任务并重建离线页面。运行时不调用 AI，不解析行动描述来决定游戏规则。

通过 API 调用生成器时传入 `questContent`；默认游戏界面和两个离线种子页面已传入本包。不传该参数的生成器调用继续创建普通街区。作者源 JSON 不能直接交给旧 ContentPack 导入按钮；它由制作脚本转为任务模板，再于世界生成时绑定为两个符合现有 DSL 的内容包。

## 绑定、关系和记忆

- 生成器版本更新为 `0.4.0`。任务候选按稳定标识和种子派生键排序，不使用游戏进行中的随机流，也不读取系统时间。同种子、相同生成器及相同输入内容版本可复现。
- 主线固定绑定当地服务用途；住所阶段使用起始住所。同一任务的居民一经绑定不会被后来遇到的人替换。
- `WorldAgent.playerRelations` 保存玩家与居民之间的 1–2 个静态背景标签：`colleague / neighbor / acquaintance / grudge / debt`。居民之间原有的 `relationships` 不被解释成玩家关系，也不参与自动演化。
- 同事、邻居、熟人等背景在新世界生成时确定；旧怨与人情债是轻量故事背景，不是自动追债或关系数值模拟。和解等后续决定写入记忆，背景标签保留其来源含义。
- 任务入口和完成选项都检查绑定居民在场与关系。只有声明了该居民为参与者的事件能写 `resident.remember`；在场校验也在效果执行时进行。
- 记忆使用内容包内登记的文本 ID，记录进居民现有 `memories`；不增加信任数值。存档验证会拒绝把一个居民的任务记忆挪给另一居民。
- 完成动作先记录当场共同经历，再推进时间。因此一次完成行动结束时居民可以按日程离开，但不会让原本不在场的人隔空获知结果。

## 内容和存档契约

新增能力声明为 `quest.binding.v1`。新增条件为 `resident.present`、`resident.relation`、`resident.memory`，效果为 `resident.remember`。事件可声明 `residentIds`；`textMode: "fixed"` 要求每个节点恰有一个文本，不创建事件随机流。旧事件继续使用原抽样与校验规则。

生成包为 `generated/cyber-apex-side` 和 `generated/cyber-apex-main`，分别拥有 `side:`、`main:` 命名空间。main 单向依赖 side，避免依赖环；即使某条人物支线没有生成，其可选旗标仍以 false 登记，保证主线条件引用合法。

`main:flag.started` 初始为 true，其余业务旗标初始为 false。每次完成既写阶段旗标，也写具体选择旗标；终局还记录所选路线。所有完成入口有业务旗标保护，重复请求沿用原执行器的幂等规则。免费退出不结算阶段。

`WorldDef.quests` 保存来源版本及哈希、绑定地点与居民、事件入口和已适配的 Journal。两条路线分卡展示，各自选择最新满足条件的步骤；支线在进入后显示，短篇不进 Journal。日志中的地点名称来自已绑定地点。

存档直接恢复内容包、关系、绑定和记忆，不调用生成器或新参考库。`0.1.0` 至 `0.3.0` 的旧世界快照继续按原内容恢复，不自动加装新主线。新任务供新生成世界使用。

- `npm run test:quests`：两条路线零资源/无支线通关、同种子完整复现、全部支线分支、退出续接、资源不足原子回滚、在场与跨时段记忆、独立日志、错误引用、存档恢复。
- `npm run check`：类型校验、全部回归、离线构建、分发检查和底层格式检查。
- 原赛博浏览器验收记录保存在 `artifacts/cyber-apex/`；当前浏览器验收入口为 `npm run test:quests:browser`，运行六街区版本。
- `npm run test:worldgen:browser`：原有世界创建、参考库、固定/生成世界切换和两个离线种子页面回归。
