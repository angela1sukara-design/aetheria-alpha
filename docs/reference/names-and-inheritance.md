# 姓名、家族姓与子代命名契约

新生成世界版本 0.11.0 起，居民保存 `personalName`（cultureId、givenName、familyNames、order、separator），`name` 是由它生成并保存的显示全名。中文文化为“林 + 清岚 → 林清岚”，西式文化为“Elena + Vale → Elena·Vale”。单名文化明确使用 single，不强制所有物种、个体都有姓。

世界配置的 residentNames 是明确编辑的**名池**，nameCulture 声明姓池、顺序、分隔符、缺省继承政策；17 题材均有显式配置。居民原型可用自己的 nameCulture 覆盖世界默认文化，幻想职业居民使用自己的中文译名及家族姓。文化不靠姓名字符串、性别、种族外形或当前职业推断。原始词库混有短名与全名，未经编辑适配的旧模板保留 single 原名，不拆“林舟”为林/舟，也不将完整名字再套一个姓。

姓名只在创建时确定，固定 seed + 实体 ID 稳定，读取、见面、交谈和换装不会重取。名池与姓池分开抽取，生成过程中优先避开已用全名；候选耗尽允许重名，以实体 ID 区分，绝不往人名后附加“·7”。同姓不证明是亲属；亲代/家庭关系必须来自实际身份记录。

## 姓氏继承

`createChildName` 是纯命名接口，返回全名、结构化姓名、亲代 ID 与最终采用的 surnameRule，调用方须在出生事务创建的同一个实体上持久保存；返回值本身不创建人物、不推进时间或写存档。

- 指定亲代：`{kind:'parent', parentId}`，完整继承该亲代记录中的姓氏数组。默认 parentA 指调用方明确排列的第一亲代；不代表父亲或母亲，不能由性别/身体判定。也支持文化默认 parentB。
- 家庭共姓/收养：`{kind:'household',familyNames:['林']}`，继承明确选定的家庭姓；不要求有已知生物亲代，不随机冒认家族。
- 双姓：`{kind:'compound',sources:[{parentId:'A',familyIndex:0},{parentId:'B',familyIndex:0}]}`。每方明确选择一个现有姓氏分量，按给定顺序组成双姓；同姓合并。默认 compound 取双方第一个分量，防止代际增长成无限长串。
- 无姓：`{kind:'none'}`，仅用于 single 文化。未知亲代姓氏不会退回随机姓；必须由调用方明确选家庭姓或合法单名文化。

子代使用明确提供的文化、名池和自己的稳定 ID。跨文化继承保留姓氏文字，不翻译、不自动改姓；姓名顺序由子代文化决定。继承后姓氏可不在当地姓池中，这是合法移民/跨文化家庭。结婚、关系路线、身体变化不会自动改姓；未来改名需要单独事务。

旧存档和固定都市 NPC 保留原 name；不重新生成，不猜测补姓。生成器版本白名单、D 性格分支和关系树校验均兼容 0.11.0，旧 0.10.0 原行为仍保留。新世界的结构化姓名必须与生成模板及 name 完全一致，读档拒绝缺失、篡改或从别的居民挪来的姓名记录。

## 正文槽位

动态人物名沿用 opponentForm，动态地名沿用 place，不新增第九种槽。词条的 `text` 与 `displayRef:{field:'name'}` 二选一。displayRef 从 context.displayValues 中按词条 binding 的 subject + instanceId 查找唯一、同 revision、来源 snapshot/engine-query 的 name；无记录、歧义、过期或非法文本则不能入槽。姓名只是展示值，不是 Tag，不从正文生成，不执行二次插值。完整全名由权威对象快照提供，拼装器不重新拼姓/名或随机取名。
