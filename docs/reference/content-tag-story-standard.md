## 1. 先决定你在制作什么

| 内容 | 放在哪里 / 使用什么格式 | 负责什么 |
| --- | --- | --- |
| 单个姓名、性格、服装、环境片段、普通对白 | 独立 Lexicon 素材库 | 提供可复用文字，不执行规则 |
| 生成地点、生态、职业原型引用、活动或事件候选 | ReferencePack | 决定生成时什么可以组合、怎样抽取 |
| 固定 NPC、地图、行动、故事分支、奖励、身体变化 | ContentPack | 定义真实玩法和权威事实 |
| 已存在事件节点的可替换正文 | TextExpansion 文本包 | 在授权文本槽内替换显示文字 |
| 某个玩家的进度 | GameState / 世界快照 | 保存实际发生的事件、身份、身体、关系和记忆 |

制作流程是：**素材生产 → 格式校验与收录 → 语义审稿 → 编辑选材与规则适配 → 内容校验 → 新世界或指定内容入口使用。** 收录、审定、接入候选、实际在本局出现，是不同状态。

固定故事直接按故事内容包制作；可以引用素材作为文字来源，但不能把完整任务塞进 `text-encounter` 或 `npc-history`。

## 2. 三种 tag 必须分清

| 层级 | 字段 | 当前实际作用 | 不具备的作用 |
| --- | --- | --- | --- |
| 素材分类与检索 | `category`、`subcategory`、可选 `tags` | 素材归档、选材与编辑检索 | 不控制抽样、身体、关系、奖励或剧情解锁 |
| 世界生成标签 | 模板上的 `environmentTags`、`requiresTags`、`excludesTags`、`compatibleTags`、`contributes.tags` | 筛选候选、传播生成上下文、调整权重 | 不等于游戏运行中的事实或任务进度 |
| Storylet 展示标签 | `StoryletDef.tags` | 已发现故事在档案中的主题展示 | 当前不参与故事抽选和条件求值 |

**已实现限制：没有统一的 `TagDef` 注册表，也没有需要继承的“Tag 类”。** 当前标签主要是字符串。分类代码有目录校验，生成标签没有完整的词表存在性校验。拼错标签可能通过结构检查，却使候选永远选不到。

`climate.wet` 不会自动包含 `climate.wet.rain`；点号只是命名约定，匹配是精确字符串比较。素材中的“机械”与生成标签、真实机械身体也不会自动互相转换。

### 3.1 如何选分类

按“这条素材的主要用途”分类，不按正文出现了哪些关键词分类。每条只有一个 `category` 和一个 `subcategory`，跨领域的辅助语义放进可选 `tags`。

| 素材 | 归类示例 | 判定依据 |
| --- | --- | --- |
| “谨慎的热心”，并给出行为例子 | `npc-trait / 处事倾向` | 描述稳定性格 |
| “逆光短绒” | `body-hair / 短绒` | 描述外观材料 |
| 角色把线束分类、夹上纸片 | `daily-work / 整理` | 描述一次具体工作动作 |
| “这件事我想自己处理，谢谢你先问我。” | `text-refusal / 拒绝帮忙` | 是可直接使用的对白 |
| 路人停在告示前擦掉水滴 | `text-encounter / 生活小插曲` | 自足单幕，没有选项和结算 |
| 接委托 → 去集市 → 回报 → 得钱 | ContentPack 故事 | 有条件、进度和结算，超出素材范围 |

没有精确子类时，先检查是不是归错大类。确实需要新子类时，按第 6 节扩展目录；不要为了通过校验随便选一个。

### 3.2 素材 tags 怎么写

已实现格式：`tags` 可省略；存在时为 **1–6 个不重复字符串，每个最多 30 个 Unicode 字符，无首尾空白**。没有标签时省略字段，不写空数组。`synonyms` 是可选近义检索词，不能替代分类。

**编辑约定：** 标签写内容中能核实、能帮助选材的语义，例如“修补”“公共空间”“克制”“机械外观”。通常选 2–4 个即可。避免重复 category 已经表达的泛词，也不要把每句中的名词都变成 tag。

```json
{
  "id": "lx.npc-trait.b0001.0001",
  "category": "npc-trait",
  "subcategory": "处事倾向",
  "name": "谨慎的热心",
  "description": "乐于帮忙，但先问清楚对方真正需要什么。",
  "examples": ["动手前先复述一遍请求。"],
  "tags": ["互助", "谨慎", "边界意识"]
}
```

这是单条结构示意，正式交付还需要批次包头、真实领取来源和对应批号。示例 ID 不能占用或覆盖已收录条目。

**本次盘点：** 已收录 10,700 条素材，目前都没有填写 `tags`；现有管理主要依靠 58 类及其子类。上述中文标签是写法示例，不是已经存在的统一受控词表。不要宣称现有素材库已经完成全量 tag 标注。

审稿状态、是否使用、来源模型放在对应管理记录中；不要用 `tags: ["approved", "used"]` 代替真实审稿或用途登记。更不能以“有尾”“成年”“已同意”等素材标签代替身体、年龄和情境检查。

## 4. 当前世界生成 tag 目录与匹配规则

### 4.1 当前随工程提供的词汇

范围：`content/generation/reference.json`、`lexicon-reference.json`、`addon-reference.json`，以及生成器产生的服务标签。

| 家族 | 当前值 | 用途 |
| --- | --- | --- |
| `climate.*` | `climate.wet`、`climate.dry`、`climate.forge`、`climate.garden`、`climate.tidal`、`climate.frost` | 6 种主环境的候选匹配；名称沿用现有实现，部分也代表产业风格 |
| `ecology.*` | `ecology.moss`、`ecology.shrub`、`ecology.lichen`、`ecology.canopy`、`ecology.kelp`、`ecology.fern` | 生态上下文；`ecology.` 前缀还用于提取区域生态标签 |
| `service.*` | `service.home`、`service.market`、`service.workshop`、`service.clinic`、`service.commons` | 地点用途，由生成器依据 `data.service` 加入当地标签 |
| 既有无前缀标签 | `waterways`、`solar`、`reclamation`、`horticulture`、`saltwater`、`insulation` | 当前环境附带的语义上下文；已有值保持兼容 |

共 23 个不同值。后续导入的参考包可能带来更多值，这不是全项目永远封闭的枚举。

**编辑约定：** 新增规则标签优先使用小写英文 `家族.含义`，一词一义，不随意混用同义拼写。既有无前缀值不直接改名；改名需要一起检查生产者、消费者、版本和旧数据。家族名称不自动产生新机制。

### 4.2 各字段到底怎么判定

| 字段 | 当前匹配语义 |
| --- | --- |
| `environmentTags` | 空数组不限制；否则任意一项命中**全局生成上下文**即可 |
| `requiresTags` | 全部命中当前上下文才能入选 |
| `excludesTags` | 任意一项命中当前上下文就排除 |
| `compatibleTags` | 空数组不限制；否则至少一项命中当前上下文。它是硬门槛，不是软偏好 |
| `weight` | 合格候选的基础抽取权重，1–1000 |
| `combination.boosts` | 命中对应上下文 tag 时，基础权重乘以 `multiplier`；每个倍率为 1–10，多个命中连续相乘 |
| `contributes.tags` | 模板被选中后，按生成阶段将标签加入对应上下文 |
| `requiresPacks` | 所需内容包都已安装才可入选；这里填包 ID，不填 tag |
| `combination.requiresTemplates` | 依赖的模板 ID 都必须已经被选中 |
| `combination.excludesTemplates` | 与已选模板双向检查互斥；检查的是模板 ID，不是 tag |

同一模板上的门槛共同生效。权重再高也不能越过环境、依赖和互斥条件。互斥模板目前按整个已选集合检查，不是只在同一地点检查。

### 4.3 标签什么时候生效

当前大致顺序：**环境 → 两个组织 → 逐地点选择地点/活动/事件 → 居民 → 最后汇总贡献。**

- 环境 `data.tags` 与 `contributes.tags` 建立全局上下文；选中的组织继续贡献全局标签。
- 每个地点继承当时的全局标签，再加入 `service.*` 与地点贡献标签。
- 地点活动先于地点事件选取；已选活动、事件贡献的标签会加入当地上下文，影响后续当地候选及居民选择。
- 地点标签不会自动传播给所有其他地点；也不能依赖某个阶段之后才添加的标签去通过之前阶段的门槛。
- 环境模板最先选择，初始上下文为空。它不能要求自己选中后才产生的 tag。

例如：一个活动只应在工坊出现，就写 `requiresTags: ["service.workshop"]`；如果只是希望在潮湿环境更常出现，用 `combination.boosts`；如果一定必须潮湿，才加硬筛选条件。

```json
    "description": "你按标记整理工具，完成交接后收到约定报酬。",
    "minutes": 20,
    "energyChange": -3,
    "moneyChange": 3,
    "healthChange": 0,
    "capabilities": ["grasp"]
  },
  "environmentTags": [],
  "weight": 10,
  "requiresTags": ["service.workshop"],
  "excludesTags": [],
  "compatibleTags": [],
  "requiresPacks": [],
  "combination": {
    "requiresTemplates": [],
    "excludesTemplates": [],
    "boosts": [{"tag": "climate.wet", "multiplier": 2}]
  },
  "contributes": {
    "tags": [],
    "npcTemplateIds": [],
    "eventIds": [],
    "tfIds": []
  }
}
```

正文中的报酬必须与 `moneyChange` 一致；动作能不能做由 `capabilities` 等规则决定。当前能力词表为 `grasp`、`walk`、`hear`、`balance`、`tailGrip`；写新能力字符串不会自动实现能力。

## 5. 当前故事展示 tag 与真实触发条件

固定街区现有 Storylet 的展示词汇共 33 个：

> 城市、协助、生活、身份、邻里、工作、交易、诊疗、装备、适配、社交、休息、夜间、机械、身体能力、探索、平衡、风险、调查、经济、恢复、TF、适应、沙龙、边界、发现、生活反馈、兽化、感官、隐藏、黑胶、跨日、失物。

生成街区 Storylet 使用 `neighborhood` 展示标签。固定 NPC 任务可以通过明确行动进入，不一定有 Storylet，更不一定有上述标签。

**已实现：** Storylet 先按地点、`conditions`、重复规则和冷却过滤，再只保留最高 `priority` 的候选，最后按 `weight` 抽取。`tags` 不参与这一步。

因此，“夜间”需要配 `time.window`，“机械尾”需要真实身体部件或能力条件，“交谈过”需要 NPC 记忆，“完成委托”需要实际事实旗标。`tags: ["隐藏"]` 也不能代替 `hidden` 和发现记录。

**编辑约定：** 同一主题沿用已有展示名称，建议每个故事 2–4 个；不得在玩家可见标签中写隐藏答案、真实凶手或秘密触发步骤。发现记录并不能替你消除标题、正文和标签中的剧透。

## 6. 新增 tag、子类、大类或机制分别怎么做

### 6.1 只扩充已有素材数量

不要新增分类或 Tag 类。选择现有词库，领取新增批次：

```powershell
npm run lexicon -- extend npc-trait ai-writer "扩充急躁、竞争心与独处倾向，保持具体行为差异"
```

继续走领取、生产、校验、收录、审稿流程。批号由工具分配；已收录 ID 不重排、不覆盖。

### 6.2 新增素材检索 tag

现有格式允许直接在条目 `tags` 内填写，无需改引擎。编辑先查同义词，约定标准写法、定义和适用例子，再交给作者使用。

给已收录条目补 tag 会改变条目内容和哈希；不能直接改 collections 后假装原审定仍有效。当前收录工具不提供通用覆盖更新：应单独设计修订与重审流程，或先在编辑文档中维护标注，保留原始收录文件。已进入适配清单的条目修改后还需重审和更新批准哈希。

### 6.3 新增素材子类

1. 先写一句定义，说明与同类已有子类的区别，并给出正例、反例。
2. 在 `scripts/lexicon/catalog.mjs` 对应行的子类列表中追加值，保留已有值。
3. 检查依赖该子类的编辑适配规则。例如姓名适配目前只接受“短名”“全名”，目录加了子类不代表适配器接受。
4. 运行 `npm run lexicon:prepare` 重建目录、任务和示例，检查生成差异，再运行 `npm run test:lexicon`。
5. 用工具领取新批次并验证一个实际样本，再开始批量生产。

`prepare` 保留领取、收录、审稿和额外任务数据；但会重建静态文件，执行后仍要审阅差异。

### 6.4 新增素材类，如 `npc-fear`

`npc-fear` 仅为命名示例，当前不存在。只有现有分类无法稳定表达、且以后需要独立检索和任务模板时，才新开一类。

编辑需在 `catalog.mjs` 的 `rows` 中增加：所属方向、唯一代码、中文名称、结构类型、计划数量、子类、变化维度、正确示例。结构类型沿用：

| 类型 | 除公共字段外的必填正文 |
| --- | --- |
| `named` | `name`、`description` |
| `trait` | `name`、`description`、`examples` |
| `phrase` | `text`、`description` |

公共字段为 `id`、`category`、`subcategory`。正式批次还含来源包头；每批校验范围为 1–50 条，实际交付数量必须与领取任务一致。

新增现有类型的类不需要创造游戏机制。重建工具包后同步更新本规范、生产范围和相关交付说明；如扩展 5 大方向本身，还要检查 `groups`、整包范围白名单、提示词和测试。若增加第四种结构类型或新字段，则须一起改校验器、格式/schema、生成模板、导入导出及测试，不能只加目录行。

### 6.5 新增生成 tag 或 tag 家族

1. 定义精确字符串、中文解释和上下文范围：全局环境还是当地地点。
2. 写明**生产者**：哪个已选模板在什么阶段贡献它。
3. 写明**消费者**：哪个模板读取它，是必需、排除还是增权。
4. 核对生产先于消费；避免“需要自己先入选才能入选”的循环。
5. 新增参考包版本，检查所有关联字段，同步记录词汇。
6. 校验参考包并生成样本；至少验证命中条件、未命中条件及没有候选时的行为。必须保留五种服务和可生成的必要候选。

**新 tag 家族不需要 TypeScript 类；新模板 `kind`、新服务类型、新 Condition/Effect 或新身体能力需要开发。** 当前 `kind` 只有 `environment / place / npc / faction / event / activity`，服务只有 `home / market / workshop / clinic / commons`。写 `kind: "quest"` 或 `service: "school"` 会被拒绝；学校可以先作为兼容现有服务的地点文字设定，再按需求开发新机制。

**待开发建议：** 如以后标签量明显增加，可增设独立受控目录，记录 tag、含义、作用层、生产者、消费者、别名与弃用状态，并加拼写及不可达候选检查。目前没有这个运行时注册机制，不能虚构 `registerTagClass()` 接口。

## 7. 固定故事怎么处理

### 7.1 先选故事类型

| 类型 | 当前制作路径 | 身份与地点 |
| --- | --- | --- |
| 固定角色主线、人物支线、跨地点任务 | ContentPack 的固定 NPC、行动、事件、旗标与记忆 | 引用稳定 NPC ID、地点 ID，不随机换人 |
| 固定街区中的小故事 | Storylet 或明确行动入口 + EventDef | 条件满足后触发；按作者定义处理重复 |
| 随机世界中的通用小故事 | `kind: event` 简单模板，或合规的 `contributes.eventIds` | 不依赖固定城市人物和地点 |
| 随机世界中的指定居民长篇故事 | 先做角色绑定与进度机制设计 | 当前没有通用的动态居民长篇故事绑定协议，需开发 |
| 只扩写已有节点正文 | 注册文本槽 + TextExpansion | 沿用原事件事实、选择与下一步 |

“固定”意味着作者确定人物、关键事实和分支契约。开始时间可以由玩家选择，也可以有条件触发；不意味着必须在某天强制发生。

### 7.2 固定故事保留为完整内容单元

每个故事先写一张制作卡，至少包含：

- 故事标识、标题、适用世界、来源，以及哪些设定已确认、哪些为 `PROPOSED`。
- 固定参与者、地点、前置条件与入口行动。
- 节点与选项：每项条件、真实 effects、下一节点和退出方式。
- 跨地点、跨日、人物不在场时如何继续；是否可拒绝、延后或重新领取。
- 进度事实、NPC 知情范围、完成或失败条件、奖励和防重复结算方式。
- 若有 TF：真实定义 ID、阶段、身体条件、冲突、暂停/取消/阻塞处理。
- 哪些正文允许扩写，必须保持哪些事实，以及读档恢复需要验证什么。

上述制作卡是编辑文档，**不是可以直接导入的 JSON 新格式**。程序负责把它落实为当前 ContentPack。

### 7.3 当前事件能力边界

当前 `EventDef` 支持 `startNode`、`nodes`、可选 `participantIds` 和 `rating`；节点类型只有 `choice`、`exit`。行动通过 `event.advance` 推进，通过 `event.exit` 清理事件。不要从旧架构稿照搬 `wait`、`narration`、`fastForwardPath` 等未实现字段。

当前 `EventDef` 本身没有 `tags` 字段。故事展示标签放在对应 Storylet 上；不经 Storylet 的固定任务可把主题写在制作卡中，不要给事件 JSON 加未知字段。

事件进入时会检查 `participantIds` 中固定 NPC 是否在场；依赖人物的故事应声明参与者并正确设置入口条件。NPC 记忆只能由含有该参与者的事件写入。不能因为玩家在别处完成一步，便让未在场人物自动知道结果。

每个选择节点须保留资源耗尽时仍可执行的推进或结算行动；它可以承受失败后果，不要求直接或免费脱身。跳过过程必须执行与正常过程相同的必要效果，在下一关键选择停下。退出节点 `onEnter` 必须有 `event.exit`，但 `event.exit` 本身不移动玩家。结构校验不替代费用和资源耗尽时的实玩检查。节点 `onEnter` 不允许递归启动或推进事件。完整场景的属性绑定与战斗返回见 [故事复刻运行约定](story-replay.md)。

### 7.4 进度、触发和结算分开

**编辑约定：** 为长任务画清“未接 → 进行中 → 待回报 → 已完成”，需要时补充“拒绝 / 暂缓 / 失败”。这些是设计状态名称，当前没有统一 `QuestState` 枚举；用已声明旗标、NPC 记忆和事件条件组合实现，并检查互相矛盾的状态。

触发只是进入故事，完成必须由实际行动结算。`tags`、正文句子、标题和发现记录都不能充当完成事实。

特别注意当前 `repeat`：

| 值 | 当前实现 |
| --- | --- |
| `once` | Storylet 被选中时就写历史，同一 Storylet 以后不再入选；不是完成后才消耗 |
| `daily` | 同一 Storylet 每个游戏日最多被选中一次，仍受冷却限制 |
| `repeat` | 不限每天次数，仍受冷却限制 |

因此，有“先离开，以后再做”的一次任务，不能只靠 `repeat: "once"` 管理。要另设稳定的续接行动，并根据接取、回报记忆或旗标开放。不要用 `event.state: completed` 代替业务完成：一次拒绝后的正常退出也可能使事件实例完成。

冷却组是共同限制：同组另一个故事刚触发也可能挡住本故事；当前按待选故事的 `cooldownMinutes` 判定。只有确实需要共享节奏的故事才放同组，避免高优先级重复故事长期压住其他候选。

奖励放在明确完成行动中，条件排除已结算状态，并同步写入完成记忆/旗标。执行器的请求防重只能阻止重复提交同一请求；不能替代任务自身的“只领一次”规则。

### 7.5 用现有薇尔维特委托作参照

现有实现位于 `content/social/pack.json`：

1. 交谈接取时写 `aetheria-social:memory.velvet.accepted`。
2. 去集市执行核对，写 `aetheria-social:flag.order_checked`；此时薇尔维特尚不知道结果。
3. 回到她实际在场的地点，通过交谈回报，写 `aetheria-social:memory.velvet.reported` 并结算一次报酬。
4. 后续交谈根据记忆改变，不能再次领取同一笔报酬；人物仍按日程存在。

这个例子说明：固定 NPC 用稳定身份；玩家完成的事实与 NPC 知道的事实分开；跨地点进度不要求把整个任务一直压在活动事件栈里。新故事采用自己的命名空间，不复用这些 ID 当新任务状态。

薇尔维特的未知年龄和未确认设定不能由素材作者擅自补成权威事实。新设定的 `PROPOSED` 标记与包的 `draft/reviewed/approved` 状态不同；包通过技术审核不等于正史全部确认。

### 7.6 固定故事能否放进随机世界

**默认保留在固定世界。** 固定城市仍由 `content/index.json` 的六个包组成；生成专用内容在生成源库中追加，不自动替换旧人物和任务。

当前 `contributes.eventIds` 只接受可移植、自足事件，校验限制包括：

- 不声明固定人物参与者，评级只能为通用内容。
- 行动不能依赖 `location.move`、`event.start`、`scene.start`、`combat.start`、`player.create`。
- 节点进入效果限安全范围；例如禁止进入时扣资源造成退出阻断。
- 每个节点都有资源耗尽时可执行的推进或结算路径；不能把跳过过程实现成免费脱身。

给固定角色故事加 `neighborhood` tag 不会完成移植。把固定姓名改成“某位居民”也不够，还要重做引用、事实归属、角色绑定与结算。

当前生成器为普通模板事件和贡献事件创建的 Storylet 默认均为 `repeat: daily`。贡献事件即使本身只应完成一次，也仍需用真实旗标和条件防重复结算；若要完成后不再抽到，应开发相应的生成 Storylet 条件配置，不能声称已有自动的一次任务策略。

### 7.7 正文、分级与真实机制

文本槽只允许 `prose_only` 替换，不新增选项、奖励、身体变化、接触、同意事实或关系阶段。未装扩展正文时使用已有回退文字。动态居民目前没有接入固定 NPC 专用的通用可选正文槽流程。

`rating`、`contentTier`、`tier`、审稿状态与普通 tag 是不同字段。不得用主题标签绕过它们。现有 NPC 成年检查使用物种阈值，尚未统一加上 18 岁下限；涉及成人内容的后续接入应按 `ageYears >= max(18, species.adultAgeYears)` 完成实际资格校验及测试，不能把这条规范描述成现已完整实装。未知年龄不视为成年。

## 8. 交付、接入与存档规范

### 8.1 素材交付

先领取 → 按任务生产 → 校验格式、ID、数量、来源与主题 → 去重 → 收录 → 单独审稿 → 适配与用途登记。

```powershell
npm run lexicon -- validate-delivery "整包交付.json"
npm run lexicon -- import-delivery "整包交付.json"
npm run lexicon -- review "审稿决定.json"
```

正式执行前使用真实文件路径和已登记领取人；结构通过不代表语义合格。`management/reviews.json` 记录审稿，`management/usage.json` 记录经过验证的目标文件和字段绑定。

当前选材清单是 `production/lexicon-authoring/adapters/neighborhood-v0.1.json`，适配器为 `scripts/lexicon/neighborhood.mjs`。它使用明确分类、条目 ID、审定状态与内容哈希，不读取素材 tags 自动拼装。增加 tags 不会自动使素材进入游戏。

### 8.2 故事或规则交付

交付至少包含：制作卡、ContentPack/ReferencePack、依赖和版本、入口与退出路线、必要的素材来源及验收结果。使用自己的命名空间，通过公开 Hook 追加入口，避免覆盖已有定义。当前公开 Hook 接受 `action`；不要照搬设计稿中尚未实现的通用 Hook 类型。

校验按修改范围选择：

| 修改范围 | 必要验证 |
| --- | --- |
| 素材目录与工具 | `npm run test:lexicon`，再验证真实交付样本 |
| 固定内容包与文本槽 | `node scripts/pack-lint.mjs`，相应故事流程与文本槽验证 |
| 生成参考包或匹配规则 | `npm run test:worldgen`，命中/排除样本与复现检查 |
| 引擎、效果或存档协议 | `npm run check` 及相应存读档、浏览器实玩检查 |

故事实玩至少覆盖：首次进入、拒绝/退出、续接、资源不足、NPC 不在场、跨日、一次结算、重复点击和关键节点保存恢复。正文与实际 delta 必须一致。

### 8.3 旧世界与旧存档

- 新素材和新生成参考库只影响之后的新世界；旧世界使用保存的内容快照，不重抽名字、身体、关系或剧情。
- 复现需要种子、生成器版本、规则、参考包及内容包输入一致；只记种子不够。
- 内容包以 `id/version/hash` 校验。已发布包不应直接覆盖后假装旧档仍然兼容；当前没有通用包迁移机制。
- 系统存在官方精确旧档升级及受限制的追加内容支持，不能据此承诺任意新故事、新旗标或新 NPC 都能无迁移热装旧档。新包应先验证兼容路径，必要时仅供新开局。
- 文本展示扩展与权威规则包分开管理；换正文不能改进度和事实。

## 9. 一页判断表

| 你想做的事 | 应该怎么做 |
| --- | --- |
| 再写 200 条性格 | 扩充 `npc-trait` 批次 |
| 给素材加“幽默”检索属性 | 可选 `tags`；先约定含义 |
| 加一个“压力反应”子类 | 编辑目录、重建工具包、验证；不要现场编子类 |
| 开独立恐惧素材库 | 论证边界后新加 catalog 类；不自动获得 NPC 恐惧机制 |
| 让某事件只在诊所生成 | `requiresTags: ["service.clinic"]` |
| 让某活动在潮湿环境更常见 | `combination.boosts` |
| 显示“机械 / 探索”主题 | Storylet `tags` |
| 要求玩家真的有机械尾 | BodyGraph 条件，不用检索 tag |
| 写固定 NPC 的跨日任务 | ContentPack + 稳定 ID + 旗标/记忆 + 真实结算 |
| 写普通随机街区插曲 | 事件参考模板，或通过可移植校验的贡献事件 |
| 给随机居民写持续个人主线 | 先开发角色绑定与持久进度支持 |
| 扩写现有故事的一段正文 | 已注册文本槽 + 文本扩展包 |
| 新增能力、服务、模板 kind | 开发类型、校验、执行与存档支持；新增 tag 无法替代 |
