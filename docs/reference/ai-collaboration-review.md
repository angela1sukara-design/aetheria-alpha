## 应保留的工程约束

- 游戏状态由 ActionExecutor 事务提交；条件、选项查询和正文溯源读取不能改变状态或消耗随机流。
- 类型、加载 Schema、初始化、效果执行和存档校验必须同步；字段、操作符和 Tag 未登记时应拒绝输入。
- 生成使用已有确定性随机流，浏览、重绘和查询不能重抽结果。
- 内容关闭成人偏好后仍可完整游玩；相关 NPC 的身份、成年智慧资格和参与条件仍单独校验。
- 事件必须有实际可执行的安全退出；旧存档使用明确前身识别，不能放宽所有包哈希检查来迁就新功能。

## 建议的协作方式

1. 先冻结共享接口：区域与地点字段、NPC 能力集合、性格标签、关系状态、存档默认值和迁移策略。记录基准版本、种子、测试命令及已知失败。
2. 每个任务交付针对基准的补丁、新增文件清单和实际测试结果。只修改领用范围，不能把整份旧文件覆盖到其他人的新实现上。
3. A/C 先整合基础结构；B/D 基于已整合的结构继续；E 在目标引用、状态机、资格与兼容契约明确后开发。共享类型、校验、生成器和生成脚本由整合者逐项合并。
4. 内容生成脚本与生成出的 JSON 必须一起交付。正文候选、已审稿素材、运行 TagDef 和实际绑定分别登记；保留未实装资料不等于实装。
5. 各模块应验证正常触发、功能隐藏、资源不足、免费退出、确定性重建、保存读取、旧档恢复以及成人偏好关闭路径。测试失败须如实报告，不能删掉断言或修改历史记录来冒充通过。
6. 合并后统一运行类型检查、规则回归、完整构建和实际浏览器流程。新世界结构变化时显式更新生成器版本和旧档识别，不悄悄重生成已保存的世界。
