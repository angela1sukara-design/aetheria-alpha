# 通用词条覆盖与规则复用方案

日期：2026-10-12。状态：设计提案；本文件不表示新增运行功能已经实现。

## 结论

10,700条可以作为Alpha 0.2日常城市内容的起步素材库。数量本身不能证明玩法覆盖率，也不值得继续以数量作为主要目标。当前统一资料包含原10,700条、环境候选667条和新写388条，共11,755条素材；编辑字典1,145个概念。仍有3,064条缺乏可靠核心拆分，其他自动映射也尚待审稿。

应优先建设“结构化对象与属性 → 参数化规则模板 → 事实查询 → 条件求值 → 现有事务结算”的通道。词条通常只选取规则模板或文字变体；一条词条无需对应一条独立规则。

## 判断够不够用

| 用途 | 当前判断 | 还需核验 |
| --- | --- | --- |
| 姓名、日常环境、生活动作、普通对白 | 有足够起步素材 | 是否适用于具体城市，重复率、语域和角色一致性 |
| 环境与身体描写 | 已有素材和可拆分维度 | 修饰对象、部位绑定、真正适用的身体结构 |
| NPC习惯、目标与价值 | 有素材，自动语义拆分较弱 | 行为意图、时间、目标对象和个人事实 |
| 机械改造、装备、工作与探索 | 字面素材不等于机制定义 | 能力、尺寸、接口、资源、环境需求和不兼容原因 |
| 多阶段任务、战斗、关系路线 | 词条不能替代连续内容 | EventGraph节点、事实、分支、结算和合法返回 |

不能将“有核心标签的素材比例”当成“可处理的规则比例”。有些姓名不需要玩法规则；有些身体词条需要几种规则共同处理。必须先定义测试场景和预期结果，才能报告规则覆盖率。

## 一份词条的职责拆开

| 部分 | 示例 | 职责 |
| --- | --- | --- |
| 核心对象 | 尾部、耳饰、街道 | 确定描述什么 |
| 独立属性 | 机械、灰色、650毫米 | 挂到明确的对象或部位实例；数量使用参数 |
| 参与角色 | 行动者、对象、观察者 | 确定规则查询谁；玩家与NPC都能使用 |
| 来源与背景 | 赛博、夜间、某人物回忆 | 区分素材背景和本局当前事实 |
| 适用条件 | 有对应尾部、处于某地点 | 决定素材或行动是否可用 |
| 文字 | 原短语、描写、对白 | 表达，不创建事实或执行效果 |

特别需要绑定修饰对象：“机械手臂、布制手套”不能展开成一个全身标签集合后，错误得出手套也是机械材质。多个条件必须能指向同一个身体部位实例；多名参与者也不能共用一份不区分人的标签集合。

数字、时间与连续状态使用参数，例如尾长、门宽、关系数值、TF进度。不要为每个数值制造新Tag，也不要由“长尾”自动填入650毫米。

## 让规则按类别复用

| 规则族 | 通用处理 | 示例与边界 |
| --- | --- | --- |
| 结构与能力 | 查询BodyGraph的真实部位、可用数量和资源 | 有翼不必然会飞；尾部存在不必然能抓握 |
| 身体与装备适配 | 对同一部位核对形态、尺寸、接口、占用 | 同一适配模板可供多种尾部和衣物使用 |
| 环境与通行 | 检查路线、净空、地面与能力需求 | 狭窄描写不直接判定不能通过，需要参数或已声明的限制 |
| 工作与消耗 | 检查能力、工具、资源和时段 | 满足条件才将行动交给现有事务，不靠职业名直接授予技能 |
| NPC与关系 | 习惯和性格调节候选权重；意愿和个人事实控制准入 | 热心不代表总会帮忙，熟悉不代表当前接受接触 |
| 事件与文字选择 | 按条件、记忆、冷却、发现状态和内容偏好挑选 | 选择文字不增加好感、发奖励或修改身体 |

这些是复用的规则族，不是声称六条具体规则就能覆盖全部玩法。每族可以有多个模板和少量专属例外，数量由真实需求决定。

## 每条规则需要什么

规则包至少应包含稳定ID与版本、适用对象、角色绑定、对象绑定、条件、准入或阻止结果、可选权重调整、失败原因、来源和适用测试。

条件支持并且、或者、否定、数量与范围、已有事实、时间和关系查询。规则声明应能解释“为什么可用／为什么被阻止”，不能只返回一个分数。

词条可按概念与属性选择模板：例如“机械尾部适配”规则供所有符合结构条件的机械尾部使用，无需为每段机械尾描写重新写规则。个人任务中的独有约定则引用稳定事实ID，不强行泛化成标签。

参数化作者格式需要编译为现有Condition与Effect；当前引擎不接受任意自创字段，不能把本方案直接填入内容包冒充可运行格式。

## 求值与冲突处理

1. 验证词条、规则、属性、角色和部位引用；未知ID明确报错，不静默放行。
2. 将角色与部位绑定到当前实例，读取权威状态；求值不推进时间、不抽取随机、不修改存档。
3. 查询返回成立、不成立或信息未知。信息未知不能被“取反”变成成立；需要该事实的准入与文字候选暂停采用，允许其他已满足条件的回退。
4. 先检查硬条件和显式禁用，再在合格候选中计算偏好权重；高权重不能覆盖身体不兼容或角色拒绝。
5. 排他属性冲突必须报告；可共存属性保留。例如灰色和机械材质可以共存；同一对象的单值颜色冲突需依据明确来源或局部区域解决。
6. 选定行动后由原事务执行效果；请求去重、失败回滚与存档沿用现有机制。

优先级只用于已经声明允许覆盖的规则，如具体角色的个别台词覆盖通用台词。它不应成为让任何特例跳过所有硬条件的总开关。

同义词用于统一ID；上下位关系用于分类检索。分类上的“有翼”属于附肢描述，不得沿继承链自动变成“飞行能力”。派生描述依赖真实事实，不将文字标签反向写回身体。

## 如何验证“处理大部分”

建立独立的代表场景集，覆盖原始58库、环境候选主题及新增常用类别。分别统计需要规则适配的素材、只需要检索的素材和纯文字素材；规则覆盖率只计算已有明确预期的适用测试。

至少测这些情形：同一模板换多个词条仍正确；多个身体部位不串属性；多人不串身份；身体变化触发重新适配；未知事实不放行；相互冲突规则能解释；没有候选时有普通文字和退出路径；反复求值不重复结算；存读与内容更新不改变已发生事实。

可将“代表场景中至少90%由共享模板处理”设为阶段目标，另列需要专属例外和仍不支持的情况。这个90%是未来验收目标，不是当前测得的覆盖率，也不能由词条数量推算。

建议顺序：先整理高频场景及预期 → 建立角色／对象绑定和规则模板适配 → 接身体、装备、环境与工作 → 接NPC与文字选择 → 输出覆盖率与例外报告。继续补词只针对报告发现的内容空缺。
