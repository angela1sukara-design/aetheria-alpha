# 工程目录与历史副本

当前开发工程只有项目根目录这一份。运行版本由根目录源码构建到 `dist/`，入口为 `dist/Aetheria-Folio.html`，也可双击根目录 `start_game.bat` 启动。历史交付包不会自动接收源码修复。

| 目录 | 作用 |
| --- | --- |
| `src/`、`content/` | 游戏源码和内容 |
| `production/` | 词库、任务及文本制作资料；部分直接用于构建和测试 |
| `scripts/`、`tests/` | 构建、工具和验证 |
| `docs/` | 接口规范、设计和历史记录；含词库验证所需资料 |
| `dist/` | 可重新构建的运行版本 |
| `node_modules/` | 已安装依赖 |
| `artifacts/` | 近期验证日志和结论，以及制作工具仍引用的日志 |
| `deliverables/tools/` | 已跟踪的外发工具包；源码仍以 `production/` 为准 |
| `../aetheria-history/` | 工程外历史归档和大型测试产物，不参与构建或提交 |

2026-10-14 的整理将旧交付目录（`deliverables/current`、`archive`、`checkpoints`）和旧测试产物收进两个 ZIP。保留所有文件的实际内容，包括解压工程中的未提交差异；没有根据文件名直接判定某份副本可以丢弃。

随后已把工程内 155.7 MB 历史备份及约 23.6 MB 测试截图、快照移到相邻目录 `../aetheria-history/2026-10-14/`，并逐文件核对哈希。主工程不再保存这些历史大文件。迁移清单为 `artifacts/workspace-cleanup/external-history-move.json`；原清单中的项目内路径记录迁移前位置。

每个压缩包旁的 `*.manifest.json` 列出文件原路径、字节数和 SHA-256。归档时逐项读回压缩包核对，并再次检查原件未发生变化，之后才移除原件。ZIP 内路径相对于工程根目录。

恢复时先将所需 ZIP 解压到独立临时目录，按清单中的原路径取回文件。需要恢复整批时，也应先比较当前工程，避免旧源码覆盖新修复。归档内的 HTML 和源码代表当时版本，不代表当前游戏。

整理脚本 `scripts/organize-workspace.ps1` 默认只预览；`-Apply` 才归档和清理，归档固定放在相邻 `aetheria-history/` 目录。它拒绝整理 Git 跟踪文件、工程外的源文件和文件系统链接，并校验归档目标必须位于历史目录内。近期验证结论与制作工具仍引用的日志列在脚本保留清单中。源码、内容、制作资料和测试夹具不属于它的整理范围。

以后发布时保留压缩包、版本记录及必要的试玩入口即可；解压核验应放在临时目录，核验后清走。不要将完整工程嵌套保存在当前工程中。
