# 海量素材词库生产准备度

## 1. 决策

**现有 58 分类内的纯文本素材可以继续按当前严格格式生产；带大量新 Tag、新字段或 NSFW 新分类的批量交付，应先冻结最小规范并完成对应校验。** 不需要等完整世界生成器或自由 NPC TF 全部实现。

现有统计为 214 批／10,700 条，108 已审定、12 暂缓、10,580 未审；882 是使用绑定次数，去重实际登记的词条是 108。所有条目目前均未填写 tags/synonyms。这意味着收录已经具有规模，但语义治理尚未被大规模数据锁死。

证据：[catalog.mjs](D:/desktop/nsfw/aetheria-alpha-0.1/scripts/lexicon/catalog.mjs)、[library.mjs](D:/desktop/nsfw/aetheria-alpha-0.1/scripts/lexicon/library.mjs)、[management/index.json](D:/desktop/nsfw/aetheria-alpha-0.1/production/lexicon-authoring/management/index.json)、[neighborhood.mjs](D:/desktop/nsfw/aetheria-alpha-0.1/scripts/lexicon/neighborhood.mjs)。

## 2. 已可复用的生产设施

- 有分类与子类清单，named/trait/phrase 三种形状；批次 1–50 条，任务有明确 producer 归属。ID 固定为 `lx.<library>.bNNNN.NNNN`，序号由批次与位置确定，已收录 ID 不复用。
- 输入严格白名单，阻止混入游戏规则；trait 的 examples 是必填。现行 tags 最多 6 个、每个最多 30 字符；synonyms 是文本表面同义项，不等于语义字典 aliases。
- 领取／收录锁与单文件原子写入；格式和归属预检、精确重复阻断、同名／近似提示；相同批次摘要可幂等重收，变更已收录批次拒绝覆盖。
- 审稿状态与使用登记独立；编译选集需 approved 与审定内容哈希一致。使用登记包含 entryId、目标相对路径、JSON Pointer、verifiedBy。
- 原词库与游戏包分离；当前适配保留既有玩法结构，替换受控文本来源。素材数量不等于实际玩法数量。

多文件整包先预检再逐个原子写入，但不是数据库式多文件事务：中途 I/O 故障可能留下部分新文件，需依幂等重试与重建索引恢复。不要宣称已经具有跨文件全有全无保证。

## 3. 大批生产前必须冻结的最小规范

| 事项 | 最小决定 | 验收条件 |
|---|---|---|
| 稳定 ID | 继续现有批次式 ID；多 AI 按领取批次隔离；修订保留原始内容哈希与版本记录，不私自覆盖 | 重复 ID、未领取／越界批次拒绝；来源 model 未知就明确未知，不伪造模型名 |
| 分类／形状 | 58 分类和受控 subcategory；新类别走一次定义流程 | 任务给出 category、kind、必填字段、子类、数量与示例 |
| Tag 字典 | 稳定 ID、中文名、定义、少量 facets、别名域、废弃／替代规则 | 不存在／歧义 Tag 拒绝进入正式带 Tag 选集；新词义先提案后发布 |
| 引用形式 | 新版本 tags 保存 canonical ID；现行 v1 只能使用其长度等限制内的批准值，其他新格式必须版本分派 | 不能向 v1 塞未知字段；别名只作导入提示／显式归一化，保存稳定 ID |
| 语义粒度 | 原子语义优先；组合交给规则；机械主题、机械材料、机械结构不同定义 | 不生产“有机械手且夜间且高信任”复合 Tag，不按每个数值造区间 |
| 参数可复用边界 | 明确部位／材料／颜色／尺寸等字段名称和来源，不要求素材直接填写数值 | 不允许词条自带 Patch、概率、能力授予、行为代码；素材所述未实现机制可标待映射 |
| 审核与统计 | collected、approved、hold、rejected、uniqueUsed、bindingCount 分开；增加已编译／机制映射统计时明确其证明范围 | 目录计数不算收录，单次绑定不证明功能存在；内容改动使旧审定失效 |
| 多 AI 冲突 | 一个字典维护入口、批次所有者、查重预检、同义提案区 | AI 不各建同义 Tag；编辑裁决语义合并，不自动覆盖别人的定义 |
| 分级扩展 | 普通／成人内容共用治理接口，但给新格式、分类与专用分级元数据明确适配 | NSFW 外部 14 分类不能宣称当前可导入；格式样例通过实际 parser 后才大量生成 |

最小交付给创作 AI：任务清单、已批准词典版本、一个可验证完整批次示例、禁止规则字段说明、重复检查与返工流程。无需提供全部游戏源码或完整 TF 实现。

## 4. 新 Tag 类的创建流程（拟定）

1. 先判断是素材管理分类、语义 Tag、实际参数还是剧情事实；不能因为词语新颖就新增类。
2. 查询现有 definition 与 aliases；同义项加入别名，语义不同才建立稳定 ID。
3. 定义适用域与反例。例如“机械”主题允许机械题材文本，不表示任何人物真的有机械身体。
4. 有少量典型素材和引用需求再登记 TagDef；若是新 library，还要明确 kind、子类与任务计划，更新版本化 parser、示例和验收。
5. 词库引用只负责分类；规则消费者、参数映射、机制接入另行开发验收。没有消费者的描述性 Tag 不自动删除，也不假装产生玩法。

## 5. 规模风险与可后置事项

当前 collection 每次会读取并验证所有批次；索引不包含 tags/synonyms。重复检查先规范化文本，近似匹配有候选截断与阈值，不能证明所有语义重复已清除。扩大到数万条后，优先优化离线导入／审稿索引，而不是先改游戏身体结构。

推荐后续独立离线倒排索引：category、tagId、approved 状态 → entryId 列表；批次内容哈希用于增量更新。它可从源文件重建，不成为另一份词条真相。首次小规模检索可以朴素过滤，测量后再加索引；语义向量和自动同义推理均可后置。

当前生成参考模板总量 2,000、每份参考包至多 500，适配选择列表至多 100；这些是玩法候选和编译选集约束，不是原素材库只能有 2,000 条。通过离线选集／适配导出受控候选，不能把全库强塞进世界快照。存档 4 MiB 上限与无限增长账本需要单独测量和方案，不能靠截断玩家记录解决。

可以后置：完整情绪／社会模拟、所有材料的物理参数、任意 NPC TF、Tag 多父关系、向量检索、分布式内容数据库、全量运行时缓存。必须先做：ID、字典语义、输入版本、批次归属与审稿统计。
