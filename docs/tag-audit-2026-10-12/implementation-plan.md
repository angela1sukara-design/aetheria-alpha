# 最小增量实施计划与兼容性

本文件只给出实施建议；本轮没有修改游戏源码、内容包或词条。用户确认后按阶段单独实现与验收，不一次重构整个工程。

## 1. 依赖顺序与阶段出口

| 阶段 | 工作 | 依赖 | 出口／优先级 |
|---|---|---|---|
| 0 规范冻结 | 批准现有 23+34 映射、字典字段、Tag/参数/事实边界；新分类示例与格式版本 | 本审计 | 允许带 Tag 的多 AI 批次试生产；P0 |
| 1 离线语义治理 | 建立共享 TagDef 字典与旧别名映射；词库／参考包离线检查、反向引用索引、弃用报告 | 0 | 一个小批次完整收录、审稿、编译；旧 v1 无 Tag 批次照常；P0 |
| 2 接入既有注册设施 | 版本化内容 Tag 定义区、Loader 所有权／引用／依赖校验、Registry 查询；素材工具用其导出 | 1 | 同一语义单一字典；不把词库全装进 Registry；P1 |
| 3 共享查询与去重复 | 从 bodyTraits/evaluate 提取实体身体访问；service.* 由 service 得出、生态子集一致性检查；小量派生规则 | 2；实体查询可先独立准备 | UI／条件／检索结果一致，派生值不存权威状态；P1 |
| 4 部件属性 | 定义默认+实例覆盖、材料／形态最小字段、受验证属性 Patch、版本化存档迁移 | 3 与版本设计 | 玩家部件修改真实生效且可保存恢复；不开发所有参数；P1 |
| 5 固定 NPC 身体与目标 | 固定 NPC 显式 body 定义／状态、scene actor 引用权威身体、TF 目标与来源、失效再校验 | 3、4 | 不再以默认玩家模板猜 NPC 身体；玩家与 NPC 改造事务均可验证；P1 |
| 6 内容检索闭环 | 小选集：身体属性→派生语义／直接参数条件→审定素材→文本表现；加入一个有实际消费者的环境属性 | 1、3；属性功能按需依赖4 | 展示正确且不改变既定事实；P2 |
| 7 按量优化 | 批次增量索引、倒排候选、生成／存档体积测量、必要缓存 | 有测量证据 | 只有遇到规模瓶颈才扩大；P3 |

阶段 1 足以开始有规范约束的素材生产；不必等待阶段 5。固定故事梳理与纯文本收录可并行，但正文不直接承担结算。

## 2. 最小实施选择

| 分歧 | 方案比较 | 推荐 |
|---|---|---|
| Registry | 独立运行时 TagRegistry 便于局部开发，但重复命名／加载／版本；现 Registry 加类型与导出需改 Schema | 扩展现 Registry；离线词典是同一来源的工具视图，不另立权威 |
| 身体 | 全新部件系统破坏图验证、TF、保存；现图增属性保留已验能力 | 增量扩展 BodyGraph，保持 parts/edges/anchor |
| NPC | 一次合并两套人物类型牵涉记忆／日程；解析接口可保留其专长 | 统一实体解析与写入路由，各自状态只存一次 body |
| 动态 Tag | 保存标签集要处理失效迁移；按需计算简单正确 | 不保存派生标签，先按需，测量后缓存 |
| 环境 | 全数值模拟需要大量机制；少量有消费者的字段风险低 | 先 service 一致性与设施／光照需求，再考虑温湿污染 |

## 3. 兼容策略：不能原地重写所有旧 JSON

### 3.1 词库与参考包

保留旧 `aetheria-lexicon-batch` schemaVersion=1 的读取；现有已收录批次不可覆盖。新字段或更长 Tag ID 用新版本形状，或独立版本化管理侧表；不能要求旧 parser 接受未知字段。迁移应生成可审查映射／新版产物，不删除原稿，保留原内容哈希、来源和旧 ID 对照。

参考包 Tag 字符串通过版本声明选择旧域别名或新 canonical ID；新包开启严格存在检查。老版本先维持精确原字符串语义，不用模糊匹配“修复”。未知旧扩展词先隔离并要求定义，不能全局自动丢弃。

### 3.2 内容包

现有 Manifest.schemaVersion=1、engineApiVersion 与 capability 白名单都严格校验；新增 Tag／属性要提供明确版本分派及能力约束。只增加 JSON 字段会被拒绝。修改包任何内容都会改变整体哈希，不能拿新包假装旧哈希匹配。

先冻结旧包快照，发布新版本；选择性支持旧、新 Schema 共存编译到内部类型。不要直接把全部已有 6 包改号而不给存档路径。Storylet 中文标签替换即使不改变玩法也改变包哈希，应与映射／存档策略一起发布。

### 3.3 存档

当前只实现有限官方迁移；Manifest.migrations 不是可直接填脚本的通用系统。建议新增持久属性／NPC body 时引入下一保存格式（例如 schemaVersion=4，最终编号实现时确定），显式执行 v3→新版本校验迁移，而不是悄悄放宽 v3 的 exact-key 检查。

旧身体缺少新参数按旧定义得到默认／未知；不捏造长度／材质细类。旧场景里的 NPC 默认身体不提升为永久真实身体，应重新绑定显式 NPC 身体；无法判定则暂停／退出场景保留进度，迁移结果需向用户说明。旧已发生 TF 的图和阶段仍保留，不重跑 Effect。

生成世界携带自己的内容包快照与 generatorVersion，原样恢复旧语义。别名归一化只在内存查询视图使用时不改变旧字节哈希；要改存档快照必须显式生成新版快照、重算哈希并记录迁移。保留旧版本适配器，不能重抽生成结果或事后改变过去文本。

新增不变量如 service Tag／生态子集检查不宜立即无条件拒绝所有历史版本：新版本严格；旧官方快照做确定性视图修复或迁移，未知第三方矛盾数据隔离而非静默猜值。

当前正文扩展与追加包能力有明确限制。完整固定故事新增 flags、NPC、身体或 TextSlot 时，不保证能走现有运行时追加入口；选择新局或单独声明并实现兼容迁移。

## 4. 逐阶段有意义的验证

| 变更 | 必需用例 |
|---|---|
| 字典与输入 | 重复稳定 ID、跨包归属、缺引用、歧义别名、替代环、废弃值；旧无 Tag 批次仍可收录；NSFW 新格式被旧 parser 明确拒绝、被新版本明确识别 |
| 生成匹配 | requires all、excludes none、compatible any、环境全局作用域、boost 乘权重与贡献顺序保持；固定种子及输入重排结果可复现；service 只产生对应值 |
| 身体属性 | 机械手+有机尾不匹配机械尾；同一部件匹配才成立；实例覆盖与定义默认正确，缺值≠零；越界单位／未知字段拒绝；未受影响部件与边不变 |
| TF／事务 | 每阶段真实图／参数变化；暂停、阻塞、恢复、取消保留已生效变化；重复 requestId 不重复改变；失败回滚；接触／装备失效同步清理 |
| NPC | 固定 NPC unknown body 不猜人形；显式 NPC 与居民使用同一身体查询；NPC TF 不误改玩家，actor 场景不持有第二份可改权威图；新种族阈值低于18时不能绕过统一成年门槛，年龄未知回退 |
| 派生检索 | 同 revision 重复 view 不改状态、RNG、时钟；TF／环境／跨时段后结果更新；文本候选满足事实和分级、回退存在；载入重算结果一致 |
| 存档 | v3 原样读；显式迁移后写新版本再读；恢复生成快照不重抽；包哈希冲突、未知参数隔离；账本／记忆／已应用阶段不丢失 |
| 词库适配 | 审定哈希失效阻止编译；未知 Tag 不混入选集；唯一词条数与绑定次数分开；未实现材料只作素材不会获得能力 |

每阶段先跑受影响测试及 typecheck；涉及身体、执行器、存档时再跑全套。浏览器用例仅在 UI／导入流程改变时运行；不为纯文档另建镜像式测试。

## 5. 本轮停止点

已完成源码审计、只读探针、当前 typecheck 与 188 项测试、逐项迁移建议。下一步需要用户选择实施范围；建议首先批准阶段 0–1 的字典与输入规范，再进入代码修改。所有优先级代表实施建议，不表示本轮存在应立即修改的线上故障。
