# Tag 架构建议：统一字典，多维管理，状态独立

## 1. 推荐与方案比较

推荐：**稳定命名空间 ID + 多维管理分类 + 独立参数／事实 + 按需派生**。扩展现有 Registry 的定义与校验设施；素材工具读取同一份字典导出。不新增一个自行维护另一套命名、依赖和版本规则的运行时注册中心。

| 方案 | 优点 | 实际成本／问题 | 决策 |
|---|---|---|---|
| 扁平自由文本 | 当前编辑最省事 | 拼写／同义无治理、跨 AI 冲突、无引用检查 | 旧格式兼容输入，不作为新规范 |
| 命名空间稳定 ID | 语义身份和显示名分离、跨包可追踪 | 要维护字典与映射 | 采用 |
| 多维分类 facets | 主题／对象／用途可交叉组织 | 要限制分类字段与含义 | 采用；分类不自动授予角色属性 |
| 单父树 | 编辑目录易浏览 | 同词多语境别扭，误把物种树当身体继承 | 仅用于管理界面／目录 |
| 多父语义关系 | 可表达更宽泛检索 | 环、歧义、隐式匹配和版本变动成本高 | 后置；将来显式 broader/related，不参与身体结构推断 |

“机械尾”“有尾”“机械部件”可分别用于检索，但不为狼耳×机械臂×黑胶腿的每种组合创造整体 Tag。完整条件通过规则组合，数值直接查询。

## 2. 字典最小字段与职责

下列是拟新增格式示意，当前 parser 不能直接读取。采用与现有 Id 一致的 `namespace:local-id`，不要求名称路径形成继承关系。

```json
{
  "id": "aetheria:body.has-tail",
  "label": "有尾部",
  "definition": "所查询实体的当前有效身体图中存在 kind=tail 的部件。",
  "facets": ["body", "retrieval"],
  "status": "active",
  "aliases": []
}
```

| 信息 | 推荐位置与规则 |
|---|---|
| id / 中文 label / definition / facets / status | TagDef 核心；ID 永久不复用，改显示名不改 ID；含义不同创建新 ID |
| namespace | 从 ID 解析，校验与所属包归属一致；不另存可矛盾的 namespace |
| aliases | 可选；旧字符串按域建立映射。一个域内歧义拒绝；中文模糊查找只给建议，不静默决定结算 |
| replacementId | 仅废弃且有明确等价替代时填写；校验目标存在且无环。不等价拆分不能机械自动迁移 |
| 来源包／作者／版本 | 复用 Manifest 与 Registry provenance；不要逐条复制包信息 |
| “静态、派生、人工导入”等来源类型 | 记录在绑定或派生规则；同一语义可由不同合法上下文提供，不硬编码唯一来源类型在词义里 |
| 被哪些内容引用 | 构建时从 JSON Pointer 扫描生成反向索引；不让作者维护 refs 数组 |
| 概率、冲突、TF 效果、行为、分级许可 | 独立规则／状态／分级字段；禁止写入 TagDef |

管理 facets 建议少量固定值：setting、ecology、service、body、material-context、theme、identity-context、content；用途可另列 retrieval/generation/editorial。目录、词条 category/subcategory、Tag facets 是三个不同层次，不能互相自动扩展。

字典可先落为离线版本化文件并提供校验，随后在版本化内容包增加可选 tag 定义区，再由既有 Loader/Registry 加载并导出给词库工具。不是要求先把全部素材塞进 ContentPack。跨包引用沿用显式依赖与包哈希；旧版 Schema 对未知字段严格拒绝，必须有版本分派。

## 3. 绑定与统一查询

三种用途要显式区分：

1. 素材语义：词条／Storylet 描述“关于什么”，不证明人物当前是什么、做过什么。
2. 生成上下文：一次生成中已选模板贡献的语义集合，保留现有匹配顺序，不冒充长期环境参数。
3. 动态实体视图：来自真实图、参数和环境的可重算 Tag，不提供手动 set/unset 状态接口。

拟新增 `DerivedTagRule` 最小包含 id、tagId、subjectKind、when。其 when 应复用扩展后的 Condition 查询 AST，不再发明另一套机械尾／湿度判定公式。现有 evaluate 还主要面向玩家，第一步提取共享纯查询并增加实体上下文，不能声称已经可对任何 NPC 派生。

建议调用链：

```text
权威实体／身体／环境
  → effectivePartAttributes + bodyTraits + environmentQuery（共享纯查询）
  → evaluate（动作与剧情条件）
  → DerivedTagRule（复用同样的查询）
  → 字典化语义视图 + 内容硬条件过滤
  → 选集内检索／独立权重与组合规则
  → 正文展示或提议行动；真实结算仍经 ActionExecutor
```

部件作用域不可省略：`exists part(kind=tail AND materialFamily=mechanical)` 才是机械尾。`hasMechanicalPart AND hasTail` 会把机械手+有机尾误判。部件 Tag 如需暴露，要携带 partInstanceId 或允许同部件谓词；跨部件检索必须显式量词。颜色、长度、能力计数应直接查询，不先造一整套数值区间 Tag。

派生规则首版禁止读取其他派生 Tag，避免隐式循环；同义映射也不具有推导效果。以后需要依赖链再编译成无环图，不通过多父树暗中引入推理。

## 4. 应派生与不应派生

| 数据／语义 | 做法 |
|---|---|
| 有尾、同部件机械尾、具备抓握 | 可按复用需要派生；执行资格仍查真实图／能力 |
| 具体能力数量、长度、温度阈值 | 直接 Condition 查询；少量真正共用的叙事区间可派生，但须唯一阈值规则 |
| 夜间 | 从当前时钟求；Storylet 的“夜间”主题不能直接等同此结果 |
| 设施可用、环境潮湿 | 有真实参数后才派生；wet 主题不会凭空产生湿度 |
| 职业、组织成员、出身、曾经历某 TF | 保留独立身份／事实记录；不能根据手臂材质或当前形态推断 |
| Storylet 的 TF／机械／黑胶／跨日 | 编辑主题；与同名身体状态和事件事实分域 |
| 隐藏、adultOptional、rating、审核状态 | 专用字段／策略；不是身体派生 Tag，更不能用来绕过年龄与参与者资格 |

## 5. 更新、保存、缓存

- 图／参数改动只有可信 Effect 写入；事务提交前统一计算资格并沿用 revalidateDistrict 清理失效装备／接触。派生视图直接读取新状态，首版不持久化标签集。
- 查询同一 revision 必须得到相同结果，不推进时钟、不消耗 RNG、不重选已锁定事件文本。参数变化后的未来检索用新结果，历史记忆和固定事实不重写。
- 加载只恢复权威状态，完成图／属性／内容版本校验后计算视图；不信任存档里的外部派生缓存。
- 暂用按需查询；以后缓存必须包含实体版本、相关环境／时间与规则版本。不要用独立可写 hasTail 作为“缓存”。

## 6. 三层分离与固定故事接入

| 层 | 可以包含 | 不包含 |
|---|---|---|
| A 素材 | 名称、描述、短句、必要语义引用、来源与审核 | 权重、状态改变、TF Patch、职业行动授权 |
| B 组合与筛选 | Condition、场景适用性、Tag 组合、冲突、候选权重、选集 | 玩家已经完成任务等权威事实 |
| C 真实玩法 | BodyGraph、身份／记忆、事件、TF、数值、战斗、事务 | 由正文自动推断并未经校验的结算 |

未实现材料／形态仍可收录为素材，但须在管理层区分“素材已收录”和“有真实机制映射”。不能为了进入词库捏造能力字段或临时把名字写成状态 Tag。

旧 AI 故事建议按“原稿存档 → 时间线／人物／确定事实清单 → EventGraph 与明确成功事实 → Action/Effect 结算 → TextSlot 或固定 textKey 正文”处理。章节标题是管理目录，故事主题可有 Tag；主角已有尾巴则写实际身体初始化／TF，而非一条尾巴标签。原稿不擅自扩写玩法，缺失事实单列待定。固定内容中有变化必须声明 Patch、阶段、回退／退出与保存；纯正文替换不得改变事实。

当前文本扩展仅 prose_only；现有追加导入也有能力限制，不能承诺任意独立玩法在运行中无条件热插入。新增固定故事可先作为版本化 ContentPack 在新局／声明兼容的载入路径验证，不能强塞入词库格式。

## 7. NSFW 与普通素材共用接口的边界

技术层可共用稳定 ID、语义字典、引用校验、来源和审核体系；内容域／分级由专用字段决定，不能让同名普通 Tag 和 NSFW Tag 产生冲突。本工程现有 58 分类的批次 parser 不认识此前外部规范中的 `aetheria-nsfw-lexicon-batch` 与 14 个 nsfw-* 分类；那是待实现的编辑规范，不是已经能导入的接口。

保留兼容入口的设计可以成立，但要先做版本化格式和分类适配；不能向当前严格 v1 JSON 任意增加 tier/rating 字段。已有 Event rating、TextSlot contentTier、文本 variant tier 与偏好是不同作用域，需在编译入口检查映射；年龄未知、缺少适用资格时回退通用文本，不能把 adult Tag 视为资格证明。
