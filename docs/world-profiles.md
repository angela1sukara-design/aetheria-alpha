# 世界 Tag 与任务配置

更新：2026-10-13，生成器版本 `0.6.0`。主线人物关系生成见[关系生成器](main-relationships.md)。

世界题材现在是实际参与生成、内容筛选和存档的 Tag。`home / market / workshop / clinic / commons` 继续作为共享服务类型，玩家看到的地点名、描述、资源、组织、居民名和主线终局由世界配置决定。六类湿润、干燥、植被、低温、热源、滨水生态独立保留，不再用生态名称替代世界题材。

Tag 完整形式为 `worlds:setting.<后缀>`。题材名取自项目已有来源主题，明确映射成上述 17 项配置；没有把全部未审定词库自动注册为运行内容。例如共享 `market` 在赛博、空间站和仙侠世界分别显示“霓虹交易所”“轨道货运交易舱”“灵材交易坊”。东方称谓仅用于对应题材。

## 主线、支线与关系

抽象目标仍是“站上顶点”。每世界两条路线、各四阶段，合计八个阶段条目。两种基础做法推进同一个阶段 flag，均可在零资源下完成；前三阶段各有一个可选支线方案。免费暂缓保留进度。任一终局完成后关闭两条主线入口，支线仍可继续。

每世界配置 18 条支线：6 条主线相关、6 条人物、6 条当地短篇。主线相关支线通过验货、设备时段安排、债务核对、通行演练和物资分配等当地选择完成，写入独立 `side:flag.*`，只解锁额外做法。人物支线依赖绑定居民到场，记录实际分支记忆。当地短篇一分钟内完成，不进入 Journal。没有强制返回报信环节。

这 306 个世界支线配置条目复用共享互动模板，再按世界绑定资源与组织，并非 306 篇独立故事。默认 7 地点、9 居民在验收种子下绑定 18 条；最小规模可能略过没有合适居民的人物支线，12 条非人物支线与完整主线仍可用。

每居民 1–2 个静态玩家关系标签：`colleague / neighbor / acquaintance / grudge / debt`。实际选择写入绑定居民的 NPC memory；不引入关系数值演化或自动派系战争。

Journal 显示实际绑定地点、下一阶段名称与目标；终局读取实际所选行动的结果。战斗、生产、商贸和统治目前均通过既有 Action/Event 选择落实，未新增军队或公司模拟。

## 文件与制作

| 文件 | 用途 |
| --- | --- |
| `production/quest-authoring/world-settings/themes.mjs` | 17 组世界参数，人工明确对应题材、地点、资源、组织与终局 |
| `scripts/build-world-profiles.mjs` | 离线展开共享任务结构、校验旗标和行动，导出作者审阅文件 |
| `content/generation/world-profile-content.json` | 注册世界 Tags 与有范围的旧来源别名 |
| `content/generation/world-profiles.json` | 运行时题材与任务配置目录 |
| `src/world/profiles.ts` | 严格解析、按种子选择、共享服务的显示映射 |
| `src/world/generator.ts` | 将世界 Tag 带入候选筛选、生成地点与人物、绑定任务 |
| `src/world/quests.ts` | 编译任务事件、轻量关系、记忆及 Journal |
| `src/world/validation.ts` | 世界身份、题材 Tag、生态和任务来源的存档一致性校验 |

执行 `npm run quests:build` 更新 JSON；`npm run build` 也会先更新。编辑题材参数或共享任务脚本，不直接编辑会被覆盖的导出文件。游戏完全离线，运行时只读取 JSON、执行已有规则。

调用 `WorldGenerator.generate` 时传入 `worldProfiles`，并在注册表中加载 `world-profile-content.json`。可选 `worldTag` 支持完整规范 Tag 或已注册的 `generation.v1` 来源别名；未指定则按种子稳定选择。世界题材 Tag 在筛选参考模板之前已生效，可用于 `requiresTags / excludesTags`。同时指定 `worldProfiles` 和旧 `questContent` 会被拒绝，避免题材与任务错配。

既有基础模板按服务应用题材显示；导入扩展中自定义职业名称保留。手工编写的扩展剧情不会被自动改写，应在扩展模板上用世界 Tag 控制适用范围。

## 存档兼容与验证

新世界保存题材 ID、Tag、名称、配置版本与哈希、生态 Tag 和任务 ID，任务绑定、实际文本及记忆保存在世界快照中。旧生态任务及原赛博示例保留兼容，旧存档按原内容恢复，不自动换题材；新配置在创建新世界时生效。

`0.6.0` 创建任务世界时自动生成以主线为根的人物关系树：路线人物圈、阶段协作人、协作与竞争边，以及主支线关联。规则读取本次主线和真实生成的 NPC，创建时按种子确定；`0.5.0` 及更早存档不补生这棵树。

历史任务包 ID `generated/cyber-apex-main`、`generated/cyber-apex-side` 为存档兼容保留，其内实际内容与任务来源按当前世界配置生成，玩家不会看到这些内部名称。

`npm run check` 覆盖类型、规则、任务、世界生成、存档和构建检查；`npm run test:quests:browser` 覆盖 17 个世界的菜单选择、Journal、人物记忆、可选支线、终局、保存刷新与零网络请求。`npm run test:worldgen:browser` 继续覆盖参考库导入及自定义职业兼容。
