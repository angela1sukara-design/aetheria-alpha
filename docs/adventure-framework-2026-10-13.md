# Tag故事、战斗成长与审查修复

日期：2026-10-13。基线：Alpha 0.2；默认增加 `aetheria/adventure@1.0.0`，世界生成版本为 `0.7.0`。该文件描述本次实际实现；写作者另读 [Tag写作规范](../production/TAG-STORY-WRITING-SPEC.md)。

## 可以直接游玩的内容

构建后打开 `dist/Aetheria-Alpha-0.2.html`，或运行 `start_game.bat`。新生成的17种世界题材均接入实际战斗与成长入口。市场可接订单、登记经营份额；工坊和公共区域可训练；市场和工坊可购买装备。可随时通过安全休息和基础护理恢复。

| 内容 | 本次实现 |
|---|---|
| 战斗显示 | 先列双方属性和已登记Tag；回合按状态、行动、造成效果显示 |
| 故事类别 | 战败、遭遇、探索、日常、交谈、任务、身体适应、结局回顾 |
| 组合故事 | 31个节点、6份敌人行为档案；共享阶段，按真实条件和倾向分流 |
| 敌人 | 总计6个，覆盖S/M/L/Boss；新增重装哨卫和带阶段变化的监理 |
| 装备 | 总计6件；新增2种武器、2种护甲，可同时穿戴并计算加成 |
| 成长 | 七项训练、技能击、难度门槛、每日有效战胜记录 |
| 经营 | 订单、投资、契约、跨日收入；声望影响订单报酬 |
| 街区后果 | 战胜、巡查、协作、调解及任务选择持续改变安全、声望和组织影响 |

装备加成在结算时叠加，保持原有总加成上限，不改写基础属性。身体变化后逐件检查适配，不兼容装备收回背包，其余装备仍生效。

战斗每次操作仍是一整个回合，行动点用作当次动作费用检查；本次没有改成可自由安排多个动作的回合制。技能击消耗15技能资源、4体力和2行动点。普通撤离首回合检定，此后可确保撤出；体力不足4或行动点不足2时可紧急撤离，不发战斗奖励。战败会进入组合故事；理智崩坏仍有原有覆盖流程。

## 经营、成长与终局

| 行动 | 费用及时间 | 实际后果/限制 |
|---|---|---|
| 训练 | 8币、8体力、4精力，45分钟 | 对应属性+1；每天总计3次，每项最多2次；有属性上限 |
| 购买 | 武器25币/护甲30币，10分钟 | 获得物品；同一件不能重复买；装备需适配 |
| 订单 | 8体力、5精力，30分钟 | 报酬12至20币，经营份额+1、声望+1；每天最多3份 |
| 投资 | 30币，45分钟 | 经营份额+2、登记契约+1；每天一次 |
| 巡查 | 10体力，45分钟 | 安全+2、影响+1、报酬5币；每天一次 |
| 公共协作 | 4体力，30分钟 | 声望+2、安全+1；每天一次 |
| 调解 | 4精力，30分钟 | 声望、影响、安全各+1；每天一次 |

跨日收入为 `min(20, 经营份额×2)` 币/日，受金钱总上限约束。每天同一敌人的首次胜利才计入报酬和有效胜利，防止在原地反复刷取奖励。L级入口需要2次有效胜利，Boss入口需要4次有效胜利和4点组织影响。

新生成主线的最终选择需要实际里程碑：经营路线要求经营份额≥6、订单≥3、登记契约≥2；治理路线要求组织影响≥5、街区安全≥5、有效胜利≥2。非最终阶段与支线会依选择登记契约、影响、份额等不同后果；最后阶段保留无条件免费退出，达到条件后可再回来。界面主线日志和最终节点会说明门槛。

这些是已经可玩且能存读的轻量循环；关系树仍保留创建时的结构，本次没有实现独立运转的军队、战争、动态派系或完整市场模拟。持续后果通过资源、报酬、入口、终局门槛和经历记录兑现，不将称号文字当作完整模拟系统。

## 故事匹配与写作接口

真实契约在 `src/core/adventure-types.ts`，内容样例在 `content/adventure/pack.json`，生成源在 `scripts/build-adventure-content.mjs`。修改内置内容应改生成源再构建，避免下一次构建覆盖手改的JSON。

`NarrativeProfile`分别保存敌人/人物引用、标签、目标列表、倾向及权重；目前目标列表首项作为本次主要目标。`defeatTags`是战败结算实际写入的情境事实。倾向权重帮助在可行候选中选择，不是动作规划器，也不创造身体能力。

每个`NarrativeNode`包含`kind`、`stage`、`textKey`、作用域标签要求与排除、硬条件、倾向权重、优先级、访问上限及选择。作用域只有`player`、`opponent`、`environment`。选择包含标签变化、真实效果与`next`阶段。

一次推进依次：

1. 合并本次事实、真实身体派生语义、时钟/地点环境语义。缓存标签不能冒充真实身体查询。
2. 筛选类别、阶段、标签、硬条件及访问上限。
3. 保留最高优先级候选，按`max(1, 节点weight + Σ(档案倾向weight × 节点倾向weight))`加权选择。
4. 保存选择结果、节点访问记录与独立随机流。查看、菜单切换、保存和读档不重抽。
5. 玩家选择后，在同一事务内验证条件、结算真实效果、更新局部标签，再选下一阶段。

每节点1至4个选择，必须有无条件且不扣资源的结束路径；每节点最多访问3次，整段最多12步。每种类别须有无条件起始回退。`next:null`结束本段并记入经历；不要在选项效果里递归开启事件、战斗或另一个故事。每次只写当前阶段，通常一至三个自然段、80至200字，选项结果单独写。

身体适应与修理必须查真实部件。内置机械尾维护只在机械尾存在且长度需要改变时出现；选择接受后才排队执行TF，十五分钟后真实长度成为650毫米。结果保存TF来源凭据；已经是650毫米时不重复提出同项调整。

运行效果：`narrative.start`、`narrative.choose`、`adventure.change`、`progression.act`。运行条件：`narrative.tag`、`adventure.compare`、`progression.available`，可组合既有身体、环境、变量和TF条件。扩展声明`adventure.v1`并显式依赖实际来源包。节点会使用内置四个`progression:action.story.*`执行入口，加载时检查其存在、动作种类及依赖。

可见`【中文标记】`用于读者核对，不由程序扫描正文反推规则。依据表仍必须映射到真实ID或实际事实。`【体力≤19】`这种数值事实由条件验证，不能自称已注册Tag。新增标签须在包内声明，不能伪造`foundation:*`。

## 五项程序缺陷的处理

| 审查项 | 处理 |
|---|---|
| A1 战斗死锁 | 零体力、零行动点仍有紧急撤离；保存刷新后同样可用 |
| A2 长期存档过大 | 超过512条事务后归档到最近256条，保留NPC/TF来源凭据、完成事件事实及去重过滤器；清理过期重复记录和无用随机流 |
| A3 短行动时间丢失 | 余韵与技能恢复各自累计分钟余数，余数随存档保存 |
| A4 失配扩展阻断启动 | 基础内容严格加载，持久化扩展单独核验、尝试依赖顺序；无效扩展隔离并保留原文，内容偏好页可显式移除 |
| A5 文本禁用刷新丢失 | 独立保存每个文本扩展的启用状态，删除、切换、重导入后状态保持一致 |

归档是有界摘要，不是保留全部原始日志。最近事务和仍被人物/TF引用的凭据保留精确结果；旧请求ID由固定大小Bloom过滤器防止重复执行。它可能保守拒绝极少数新ID，界面可重新发起新请求；不会因此重复发奖励。长期运行测试连续执行一万次实际行动，存档仍小于1MiB，并能正常恢复。不能以此宣称任何无限规模内容和任意数量人物都能永远落在4MiB内。

旧公寓休息补回体力，生成世界的劳动、恢复及移动成本统一接入；按钮展示移动的实际体力成本。剧情选项的资源消耗提示与免费退出区分。

## 旧档与验证

旧固定世界存档按原内容校验后增量接入新包与状态，不删除原文件；旧的生成世界继续按存档内的世界、任务和内容快照恢复，不强改为新地图和新任务门槛。体验新生成内容需创建新世界，原档可保留或先导出。

规则回归包括：真实短步行累计时间；一万次实际行动后的保存；归档NPC/TF凭据；故事中途读档；维修改变真实身体；两条主线经真实经营或战胜达到门槛并完成；17种题材的真实战斗入口。浏览器另验证零资源脱困、Tag故事、训练和装备、经营、消耗提示、扩展状态恢复、离线与手机宽度，并重跑原有流程。

执行入口：`npm run check`，`npm run test:adventure:browser`，以及README列出的既有浏览器检查。证据存于`artifacts/adventure-*.log`和`artifacts/adventure-browser/`；最终通过数量见审查报告的修复复查记录。
