# 以太都市｜装备槽位、装备族与消耗品制作卡

## 0. 基线事实与提案边界

### 0.1 已从指定提交核验

- 默认内容索引加载 `core / world / reshaping / social / recovery / district / foundation / adventure` 八个包；世界主题共 **17** 种，规范世界 Tag 为 `worlds:setting.<后缀>`。
- 现行 `EquipmentSlot` 是 **`weapon` / `armor` / `cosmetic`**，并非下面拟定的六槽；`EquipmentDef` 含 `id/name/requires/description/slot/bonuses`。`cosmetic` 不计数值加成。
- `adventure` 包有 **4 件武装/防护装备**（两把武器、两件防护），`district` 包另有 **2 件 `cosmetic` 衣物**。现有装备加成字段仅 **`attack` / `defense` / `evasion`**，且战斗结算有单件与总和上限，不能把其他战斗属性写成已支持的装备 `bonuses`。
- `DistrictState.inventory` 目前是装备 ID 列表，`equipment.wear/remove` 支持穿脱；未确认通用可堆叠消耗品、数量、使用行为、自动限时 Buff、随机掉落和通用商店表。购买现有武装由专门 action 处理。
- `content/core/pack.json` **实际注册** `core:health`、`core:energy`、`core:stamina`、`core:sanity`、`core:skillResource`，以及 `core:attack/defense/speed/skillPower/hit/evasion/crit` 等。`core:sanity` 初始为 0，战败会使其**增加**，达到 100 触发 `core:flag.sanity_break`；本卡将 `core:sanity −` 作为减轻这项累积值的提案，**不等同于自动清除崩溃标记或结束结局**。
- `var.change`、`flag.set` 在核心效果契约中存在；但 `flag.set` 本身**不会自动按分钟过期**，也不能凭空使用未登记的旗标。本文 85 个消耗品先只列已存在变量的加减方向，不声称已有服用、堆叠或计时功能。
- 即便一些其他变量在核心包中存在（如 `core:desire`），本制作卡也按委托**主动排除欲望、纯洁度等方向**，不借此扩设成人变量。

### 0.2 设计约定（均未实装）

- 下文 `slot.*`、`equip.*`、`FAM-*`、`CONS-*` 是**局部编辑 ID 草案**，不占用真实命名空间，不是 `TagDef`，不代表注册过。
- 类别与槽位关系先确定，再创建装备族，最后才拆各族的材料、地区、等级、稀有度、外观和数值变体；所有世界装备族的**变体状态均为「待细分」**。
- 凡写 `变量 +` / `变量 −`，只表达作用方向，**不指定数值、持续时间、价格、可用阶段或调用代码**。战斗辅助归类按用途划分，不暗示永久提升或自动 Buff。
- 稀有度为制作分档，而非已存在的随机权重/掉落算法。主题限定属于内容筛选建议，不是词库 Tag 注册。

## A. 装备槽位草案（先定）

| 槽位编辑 ID | 显示名 | 可装大类 | 同槽/跨槽互斥草案 | 空槽默认 | 状态 |
|---|---|---|---|---|---|
| `slot.head` | 头 | 防具、饰品 | 头部只容 1 件；帽与头盔互斥；需真实适配部位 | 空、无加成、无默认物品 | proposed |
| `slot.body` | 身 | 防具、饰品 | 身部主件只容 1 件；与饰品槽独立（除非物品特别标冲突） | 同左 | proposed |
| `slot.hands` | 手 | 防具、饰品、工具 | 双手/手套视为 1 组合槽；与持握槽**不默认冲突**，只有装备声明占用同部位时才冲突 | 同左 | proposed |
| `slot.legs` | 腿 | 防具、饰品 | 腿部只容 1 件；不同下肢形态需适配，不强行假设人腿 | 同左 | proposed |
| `slot.accessory` | 饰品 | 饰品 | 当前先限 1 件；多饰品子槽以后讨论，当前不添加 | 同左 | proposed |
| `slot.held` | 持握 | 武器、工具 | 武器/工具共用 1 槽；双手器具需可核查的握持能力数量；不偷偷添加副手槽 | 同左 | proposed |
| `slot.tail` | 尾 | 防具、饰品 | 必须实际具备相应身体部位；同槽 1 件；不能仅凭世界题材推断有尾 | 同左 | **proposed 扩展** |
| `slot.wings` | 翼 | 防具、饰品 | 需真实翼部 BodyGraph 查询；同槽 1 件 | 同左 | **proposed 扩展** |
| `slot.other` | 其他部位 | 按具体物品声明 | 只有指定部位存在时才可穿戴；不能泛化为万能槽 | 同左 | **proposed 扩展** |

**槽位映射边界：**现有 `weapon` 大致对应未来 `slot.held`，现有 `armor` 需进一步拆到头/身/手/腿，`cosmetic` 不能直接等同饰品槽（它现在是**无加成的现有槽类型**）。这只是迁移方向，绝不代表目前已映射。提案中空槽不会产生罚值、被动效果或虚构默认物品。

**身体匹配边界：**工程已有 `body.hasPart`、`body.matches`、`body.hasCapability` 等查询；具体装备应根据真实部位与能力判断。不要自造 `body.has-tail` 这类看似已存在的条件 ID，也不能把 `balance` 普遍当成“确有尾巴”。

## C. 消耗品（只对应已有变量）

### C.1 类别与效果边界

| 编辑分类 ID | 显示名 | 本卡允许的效果字段 | 说明 |
|---|---|---|---|
| `cons.recovery` | 恢复 | `core:health +`、`core:energy +`、`core:stamina +` | 即时加值方向，数值待平衡 |
| `cons.combat` | 战斗辅助 | `core:skillResource +`、`core:stamina +`、`core:energy +` | 表示战斗中资源补充的设计用途；实际使用时点/行为仍需实现 |
| `cons.explore` | 探索 | `core:energy +`、`core:stamina +`、`core:sanity −` | 不暗示地图扫描、潜水呼吸、抗寒、采集加成等未实装能力 |
| `cons.adult` | 成人可选 | **仅与上面已有变量同构的加减** | **单独内容门**：只作为待选类别，不铺设具体物品；不得绕过年龄、资格、偏好和同意检查 |

- `core:sanity` **已实现**，但数值向上累积才有战败崩溃风险；本卡所有「宁神/安神」名字都对应 `core:sanity −`，不是凭名字附加“免疫精神损伤”。该减值**不自动清除** `core:flag.sanity_break`。
- `core:skillResource` **已实现**，与 `core:energy` 不同；两者不能因为名字带“能量”就混用。
- 战斗属性临时增益（攻击、命中、暴击、速度等）在此**不写成一次 `var.change` 后的永久成长**。若以后要做时限效果，需先定已登记旗标、应用/到期清除与存档规则；目前**没有**合格的“自动短时 flag”可直接声称已实现。
- 不新增变量 ID，不用欲望/纯洁度；不把文案形容当作新效果；单次效果量、堆叠数量、使用行为、商店价格全部**待工程和数值确认**。

### C.3 后续变体拆分原则

- **先区分用途，再做数值：**同一个名字不能因为颜色换了就当新机制；同类物品可在来源、价格、携带规格、数量上拆变体，但不在本卡内发明“耐寒值/氧气值/毒素值”等参数。
- **理智处理：**只列 `core:sanity −` 的数值方向，不改变崩溃 Bad End 或既有全局战败规则。
- **时限旗标：**本轮不列任何假定自动计时的 Buff；如果确需短时效果，须另做系统能力确认，且只在已存在字段基础上制作。
- **内容门：**成人可选未提供物品，若今后提出，须单独审稿并遵守成人偏好与资格检查，不能仅凭主题 Tag 激活。

## D. 挂接建议（仅是可供落地时评估的入口）

| 场景/目标 | 已核对的查询、Tag 或元数据 | 建议出现的物品 | 未实现边界 |
|---|---|---|---|
| 普通市场/交易所 | `environment.service = market`；叠加 `worlds:setting.<后缀>` | 普通级武器/防具、健康/体力消耗品、当地饰品 | 不是现成动态商店目录；世界差异由主题配置决定 |
| 工坊/装配厂 | `environment.service = workshop` + 对应世界 Tag | 工具族、加固防具、战斗辅助用品 | **不**发明耐久度、修理药剂或生产材料消耗规则 |
| 诊所/疗养站 | `environment.service = clinic` + 对应世界 Tag | 对应主题的恢复品（优先 `core:health`） | 当前仅作为商店库存建议，不等于现有诊所已经售卖 |
| 聚落公共区/任务补给点 | `environment.service = commons` 或真实地点的 `locationProfiles[].tags` | 通用探索补给、低稀有当地小物 | 不等同自动任务奖励或探索掉落 |
| 低阶遭遇候选 | `EnemyDef.tier = S`；可借 `EnvironmentEnemyRule.requiresTags / excludesTags` 选择敌人 | 基础消耗品、偶见普通饰品 | **`tier` 是敌方元数据，不是 enemy tag；没有默认胜利掉落** |
| 中高阶遭遇候选 | `EnemyDef.tier = M / L` | 改良防具/武器、战斗辅助用品 | 仅在胜利结果设计中挂接，不新增怪物属性 |
| 首领/特殊遭遇候选 | `EnemyDef.tier = boss`，或经核验的环境 Tag + 配置规则 | 稀有或 epic 主题装备族候选 | “史诗”不是默认掉率；不得将敌人素材标签误作掉落事实 |
| 主题专属补给 | `worlds:setting.cyberpunk` 等 **17 个真实世界 Tag** | 只在该题材分配本表名称池与族 | World Tag 是题材/筛选事实，不保证物品存在于某玩家背包 |

**参照现有实例：**`progression:enemy.raider`（S）、`progression:enemy.sentinel`（L）、`progression:enemy.overseer`（boss）是当前包内的三个实例，不代表未来所有世界都必须复制这三个敌人。现有 `locationProfiles[].tags` 是地点环境语义，不能当成玩家物品/已掉落事件证据。

### D.1 将来挂接前的检查点（不是本轮施工）

1. 确认六槽数据结构及多件穿戴持久化，兼容已有 `weapon / armor / cosmetic`；不让 cosmetic 变成有属性的伪防具。
2. 确认物品持有数量、消耗与使用条件（现有 `inventory: Id[]` 并不足以直接代表可堆叠消耗品）。
3. 决定稀有度权重、价格、数值与战斗阶段是否允许使用；不修改现有装备加成上限。
4. 设计地点服务到候选商店/奖励的挂接层，并验证世界主题过滤和实际场景事实。
5. 若需要临时旗标，先设计声明、持续时间与到期清除（含存档恢复），**而不是直接把 `flag.set` 当计时系统**。
6. 全部只是作者制作卡，不写 `pack.json`，不对词库条目写 `approved` 或其他审定结果。
