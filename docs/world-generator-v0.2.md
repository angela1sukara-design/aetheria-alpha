# 世界生成器 v0.2

继续 Alpha 0.2，在 `79fd967` 基线上扩充 v0.1。固定以太都市仍是默认框架测试世界。生成器创建初态，WorldSimulation 根据保存的日程推进居民，所有行动继续使用原 Registry、ActionExecutor、Storylet、BodyGraph/TF 和 SaveCodec。

## 直接试玩

- `dist/Aetheria-Alpha-0.2.html`：固定测试世界；从“世界”菜单生成随机街区。
- `dist/WorldGenerator-Seed-7.html`：已生成的晴砾街区。
- `dist/WorldGenerator-Seed-42.html`：已生成的林荫街区。

三个版本均可直接离线打开。两个种子版本使用包含生成器版本号的独立手动存档槽，保留旧版种子存档。若本机曾保存过旧生成参考库，可在“世界→管理生成参考库”中恢复默认，再生成新街区；这个操作不改变当前世界或旧存档。

先试地点中的日常活动，再用“看看在场居民”轮流打招呼，选中后交谈或协助。“留意街区与附近的人”继续触发 Storylet。页面会显示在场人数和下一次按日程到来的时间；没有居民时可以短时等候、休息或前往别处。已认识的人保留在人物册中。

## 默认内容规模

| 内容 | 数量 | 实际用途 |
| --- | --- | --- |
| 主生态 | 6 | 环境、产业、地点风格与组织候选 |
| 地点模板 | 60 | 每种生态覆盖5种服务，每种服务2个变体 |
| 日常活动模板 | 21 | 进食、整理、阅读、公共劳动、护理和观察等 |
| 事件模板 | 42 | 依环境与服务选取，每地点最多2个不同初始事件 |
| 组织模板 | 12 | 每生态2个组织，保存协调活动与分布 |
| NPC引用模板 | 11 | 9个生成专用原型引用，加2个旧职业兼容引用 |
| 生成专用居民原型 | 9 | 摊贩、电工、信使、烘焙、缝补、护理、档案、园艺、水务 |

合计152个参考模板。实际街区仍默认7个地点、9名居民，支持5–20地点、3–40居民。模板数量是内容库规模，不代表每个世界全部出现。

生成专用内容放在 `content/generation/neighborhood-content.json`，只加入生成源 Registry。固定世界的 `content/index.json` 仍为原六包清单，旧人物和任务没有被新居民替换。

每个地点保留免费休息、工作、旅行、事件和居民入口；按服务类型再选两类具体日常活动。所有诊所始终有免费体况恢复入口，不依赖随机活动是否抽中。旅行与休息不需要金钱或精力，资源耗尽仍可继续。

## 新增字段与兼容

参考包仍使用 `aetheria-reference / schemaVersion: 1`；规则包仍使用 `aetheria-generation-rules / schemaVersion: 1`。本轮为可选字段与新模板类型，旧字段格式继续受支持。

规则包新增：

| 字段 | 范围 | 缺省行为 |
| --- | --- | --- |
| `eventsPerLocation` | 1–3 | 1个事件 |
| `activitiesPerLocation` | 0–3 | 不追加活动 |

候选不足时保留已有的不同候选，不重复填充；必需的首个事件仍必须有合法候选。默认值分别为2与2。

地点模板可选 `data.ambience`，包含 `morning/day/evening/night` 四个非空字符串。分别用于06:00–10:00、10:00–18:00、18:00–22:00、22:00–06:00，编译为已有 SceneText 与 `time.window` 条件。仅改变描述，不在渲染时抽样、推进时钟或声称某个未知 NPC 已到场。

新增 `kind: activity`，沿用其他参考模板的环境、标签、组合与包依赖规则：

```json
{
  "label": "参与空筐分类",
  "description": "你按编号分类空筐，交接后收到报酬。",
  "minutes": 25,
  "energyChange": -5,
  "moneyChange": 5,
  "healthChange": 0,
  "capabilities": ["grasp"]
}
```

这是模板的 `data` 对象，完整外层见默认参考 JSON。分钟限5–120，精力变化−12至12，零钱变化−8至8，体况恢复0–8；能力必须是已有 BodyGraph 能力。活动被编译为原 `var.change`、`clock.advance`、`body.hasCapability`，费用不足时整项事务回滚。这些规则字段不属于基础词条文件。

居民原型可选 `dialogue: { intro, repeat, help }`，三个字段均为普通非空文本。原居民互动逻辑读取已保存模板中的对白，交谈与每日协助的记忆、信任及报酬仍由既有执行器处理；文字不能自行写入关系或身体变化。

`world.encounter` 新增可选 `events` 布尔字段，缺省为真。设为假时只轮流选择实际在场居民，不抽取事件或消耗 Storylet RNG；原有调用不受影响。

## 生成与模拟的改进

- 先覆盖有兼容职业的工作地点，再重复分配，住宅和诊所也可以有符合规则的工作者。
- NPC仍先建立稳定身份、实际身体、性格、职业、组织与关系，再进入保存的全天日程。
- 地图在不同网格内取确定性偏移，20地点上限下节点也不重叠；路线仍先生成双向连通树，再加捷径。
- 活动与事件贡献的当地标签在后续居民选择前生效。
- 公共到达信息只读已保存日程，不显示未认识的名字或隐藏事件。
- 23:59时按实际位置检查生成居民，不再被旧模板窗口错误清除；固定世界仍沿用原规则。

## 存档与复现

新世界记录 `generatorVersion: 0.2.0`、规则及参考包版本/哈希、内容源、参数和选择记录。旧 `0.1.0` 世界继续接受并使用原内容快照；读取不运行生成器。真实已发布v0.1种子42存档保存在压缩测试样本中，验证逐字段恢复及继续行动。

同种子、同规则与同内容输入能复现完整初态。种子42本版为林荫，v0.1为雾潮，是参考库和版本改变后的正常结果；旧存档仍然保持雾潮。不要用种子单独标识跨版本世界。

## 后续词条

词库继续独立收录。待用户交回素材后，先校验、去重和审核，再把选定文本映射到地点描述、环境时段、名字、性格与职业对白等字段。既有数值、条件、动作和存档不会由词条正文修改。详见 `worldgen-lexicon-integration.md`。

## 验证与未实现

`npm run check` 验证类型、180项自动化测试及完整构建。`npm run test:worldgen` 包含v0.1基础验收与v0.2专项；浏览器命令继续为 `npm run test:worldgen:browser`，原Alpha0.2回归为 `node tests/alpha02-browser.mjs`。

仍未实现多区域地图、逐边通勤、每职业独立轮班、完整经济和政治模拟、职业迁移、NPC自主TF、个人长篇剧情及实时AI。当前是具备实际活动和居民日程的随机街区。动态居民未接入固定NPC专用的可选正文槽协议；这不会阻止日常交谈、协助和普通事件运行。
