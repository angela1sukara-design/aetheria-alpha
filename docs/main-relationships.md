# 主线人物关系生成器

更新：2026-10-13，生成器 `0.6.0`。

## 自动生成的层级

主线目标是最大关系层：根节点为当前世界主线，下面是 2–3 条路线人物圈，再下面是各阶段的协作角色和真实居民。共享的是规则，NPC 身份、人物圈成员、核心联络人、阶段协作人和关系边都在创建世界时自动确定，没有固定 NPC 名单。

生成器读取本次主线 ID、路线、阶段和地点服务需求，结合本次生成的 NPC 工作地点、住处、日程与世界种子决定结果。种子相同但主线不同，分配仍可能不同；种子、主线、NPC 和规则完全相同时保持稳定。选择使用独立稳定排序，不消耗地图或运行时 RNG。

每条路线先保留一个真实且不同的核心联络人，再按工作服务与阶段的匹配程度、人数平衡和稳定排序分配其他居民。每位居民有一个主要人物圈，圈大小最多相差一人。

每个阶段按所需 `locationType` 选择有真实到访日程的协作人，优先本圈并分散工作量；必要时可由另一圈的人跨路线协作。联络地点可能是同类型的另一处地点，会按实际日程显示。没有合适居民则保留公共联络点，不虚构人物、不要求主线等人。

## 人物关系与任务

各人物圈内部生成相连的协作树，优先使用真实的同事或邻居关系，其余为主线协作关系；路线之间建立稀疏的竞争联络，再补充少量真实同住或同工作地关系。整个网络连通，每居民 1–4 条 NPC 关系边，双向一致、不指向自己、无重复边。竞争表示围绕同一顶点的路线竞争，不自动触发仇恨、战斗或派系战争。

玩家与居民的五类标签仍独立保留，每人 1–2 个。人物支线绑定会在现有标签容量和可到场候选内，优先选择对应主线人物圈与阶段协作人。不会为了圈归属绕过居民日程或突破关系数量限制。

主线相关支线通过行动实际检查的独立支线 flag 关联到阶段，不从故事文字猜测影响。人物支线关联实际绑定居民的主要人物圈，必要时关联其对应阶段；当地短篇保持无主线依赖。已有主线基础做法和免费退出继续可用，阶段协作人是关系角色，不是新增的强制任务门槛。

## 展示和保存

人物册显示“主线人物关系树”，按路线展开阶段和联络角色。未结识居民显示匿名占位，不提前透露姓名。结识后可从树中打开人物档案，档案显示主要人物圈、协作阶段、参与支线和关联人物；未知关联人物只显示数量。界面只读取状态，不生成关系或推进时间。

层级、角色、支线关联保存在 `WorldDef.relationshipTree`，实际 NPC 关系边保存在 `WorldAgent.relationships`。创建完成后保持静态，剧情选择继续写入现有 NPC memory，不运行完整社会模拟。

读档直接恢复快照，不用当前主线内容重算。校验根目标、路线与阶段次序、居民唯一归属、日程可达、支线 flag 关联、协作与竞争边、关系双向一致和连通性；无效输入隔离，不能通过读档悄悄补齐。

`0.5.0` 及更早世界保留原关系，不自动补生新关系树。新建世界使用新生成器。没有任务内容的旧式生成 API 保留原轻量关系方式。

## 代码与验收

- `src/world/relationships.ts`：自动生成、人物圈、联络角色、关系边及支线关联优先级。
- `src/world/relationship-validation.ts`：保存和恢复的结构及事实一致性校验。
- `src/world/quests.ts`：在主线地点确定后生成关系，再绑定支线。
- `src/ui/relationship-tree.ts`：关系层级、人物档案和匿名展示。
- `tests/main-relationships.test.ts`：同种子稳定、不同种子变化、同 NPC 池换主线、服务需求改变、3/9/40 人口、三路线、无合适联络人、非法快照与真实 `0.5.0` 旧存档。
- `tests/world-profiles-browser.mjs`：树形层级、匿名与结识后显示、手机布局、人物档案、主支线推进和存档刷新。

执行 `npm run check` 和 `npm run test:quests:browser` 验证。游戏完全离线，运行时不调用 AI。
