# 六类街区主线与支线

> 历史方案，已退出默认入口。六类标签现作为生态环境保留，世界题材与任务由独立的世界 Tag 决定。当前实现见[世界 Tag 与任务配置](world-profiles.md)。本文件和作者源继续用于旧内容兼容与回归。

更新：2026-10-13。下文记录先前按六类生态绑定任务的方案。

## 终局与路径

共同完成条件仍是 `main:flag.top_reached`，玩家看到的称号、目标、阶段与选择随街区改变。

| 街区 | 经营路线终局 | 公共事务路线终局 | 当地核心资源 |
| --- | --- | --- | --- |
| 雾潮 | 百渠总管 | 雨棚盟首 | 水渠、泵房、避雨棚 |
| 晴砾 | 镜阵执掌者 | 凉荫议长 | 镜板、加工时段、遮阴通道 |
| 林荫 | 种源总藏主 | 绿廊议长 | 种源、苗圃、树冠连廊 |
| 霜港 | 暖网总调度 | 冬港守望长 | 暖管、保温储备、夜间廊道 |
| 炉巷 | 百炉总匠 | 工联执印人 | 回炉材料、工艺样规、公共检修 |
| 咸汐 | 千栈总商 | 潮路领航人 | 防潮仓栈、浮架、高潮与低潮通路 |

每类两条路线，每条四阶段，共 48 个阶段条目。每阶段有两种无需支线、无需资源费用的完成方式，仍推进同一阶段旗标；前三个阶段各有一个相关支线提供的第三方案。所有事件都有免费暂缓出口。两条路线可并行准备，任一终局完成后关闭主线入口，支线继续开放。

结局 Journal 从实际所选终局行动读取结果，不再按固定路径 ID 写死首富或军阀。路线的下一步使用已绑定地点名；无人物参与的支线不会提示等待居民到场。

## 支线数量与互动

每类有 18 条：6 条主线相关、6 条人物、6 条当地短篇。共 108 个街区支线条目，包含 60 条街区专属故事与 8 条各街区共享的日常故事，即 68 条不同故事；共享故事没有通过改名计作独立创作。

- 6 条主线相关均为本街区专属故事，覆盖两条路线的前三阶段。现场分配水额、比较样规、商议留种、安排热额、划分准备工时、处理仓单损耗等选择会完成独立支线旗标，并开放一个主线额外方案。主线入口不检查这些旗标。
- 6 条人物支线包括 2 条当地专属旧怨/人情债故事，以及 4 条共享的邻居、同事和熟人故事。不同选择记入当场参与居民的记忆；完成后不增加关系数值。
- 6 条短篇包括 2 条当地专属声音/光线/物件互动及 4 条共享短篇。每次耗时一分钟，在当地完成，不进入 Journal。

标准 7 地点/9 居民规模在验收种子下每类绑定 18 条。最小 5 地点/3 居民世界可能缺少符合背景与日程的人物候选，此时略过相应人物支线；12 条不依赖人物的支线和两条完整主线仍可使用。每居民保持 1–2 个静态关系标签，不引入社会模拟。

## 制作与加载

| 文件 | 用途 |
| --- | --- |
| `production/quest-authoring/neighborhoods/worlds.mjs` | 六类街区的终局、48 个阶段、各阶段两个基础方案；人工维护源 |
| `production/quest-authoring/neighborhoods/sides.mjs` | 60 条当地故事与 8 条共享故事的正文、两种选择及结果；人工维护源 |
| `scripts/build-neighborhood-quests.mjs` | 展开结构化任务树、明确的可执行选择、可选支线条件和旗标，校验后打包 |
| `production/quest-authoring/neighborhoods/{wet,dry,garden,frost,forge,tidal}/quest-tree.json` | 按用户指定结构导出的可审阅任务树；构建时重新生成 |
| 同目录 `execution.json` | 明确的按钮、结果、时间、条件与记忆；构建时重新生成 |
| `content/generation/neighborhood-quests.json` | 六类街区的任务目录，默认游戏和离线 HTML 使用 |

修改人工维护源后运行 `npm run quests:build`，不要只修改会被重新生成的 JSON。`npm run build` 也会打包任务并重建全部离线页面。生成时先选环境，再按规范化后的 `climate.*` 标签精确选择一套任务；缺失或歧义会中止本次生成，当前游戏不被替换。

生成器仍接受单个 `aetheria-quest-content` 模板，也接受 `aetheria-quest-catalog` 目录。原赛博作者源与 `content/generation/cyber-apex.json` 保留为可独立使用的示例，默认六类街区不再加载它。

底层绑定、关系、记忆、条件和效果协议沿用[原任务接入说明](cyber-apex-integration.md)。生成包沿用 `generated/cyber-apex-main` / `generated/cyber-apex-side` 历史标识，以兼容原存档；当前任务来源由 `WorldDef.quests.id`、来源哈希和完整内容哈希标识，历史包标识不决定世界主题。

## 确定性与存档

生成器版本 `0.4.1`。任务匹配只使用已经选定的环境与已打包内容；地点与居民绑定仍按种子和稳定标识派生排序，不使用运行时随机或 AI。相同生成器、种子和内容输入可复现。

存档直接恢复当时的任务包、地点、居民、关系与 Journal，不重新匹配目录。`0.4.0` 的赛博任务存档和更早的世界仍按旧快照恢复；新街区内容通过重新生成世界体验。已有进度不会自动改写成新的称号或剧情。
