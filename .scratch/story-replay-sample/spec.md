# 故事复刻：黑沼陷阱验收小样

## Problem Statement

玩家需要确认故事复刻确实读取本局属性、产生真实后果，并且“跳过”只省略过程描写。仅有规则文档、通过测试或换了姓名的固定段落，不能证明这些体验已经成立。

此前已经完成故事绑定与结算链路。本轮把已有实现收成一个可直接试玩的小片段，不继续扩展机制或故事数量。

## Solution

提供同一条黑沼故事的三个独立试玩入口：同一世界的体力充足与耗尽状态，以及另一个真实世界中抽到不同材质的耗尽状态。入口使用正式游戏界面、现有内容包、正常行动事务与有效存档，不另做演示状态机。

先通过技术验证，再交给用户判断叙事、节奏和选择是否符合期待。用户验收前，体验评价保持待定。

## User Stories

1. 作为玩家，我希望打开小样就到达冲突点，以便直接判断选择是否有意义。
2. 作为玩家，我希望体力充足时能付出代价挣脱，以便属性带来实际优势。
3. 作为玩家，我希望体力耗尽时正文和行动门槛有所变化，以便状态参与叙事。
4. 作为玩家，我希望零资源仍能承受后果并推进，以免故事卡死。
5. 作为玩家，我希望另一个世界的实际对手与材质改变正文和身体结果，以便确认差异来自数据。
6. 作为玩家，我希望正文中的地点确实存在于当前地图，以便故事与世界相连。
7. 作为玩家，我希望受困后留下真实覆层和残迹，以便后果可以继续处理。
8. 作为玩家，我希望跳过与正常继续花费相同时间并保留相同后果，以免跳过成为免费脱身。
9. 作为玩家，我希望跳过在下一次清理或保留的选择前停下，以便自己决定结果。
10. 作为玩家，我希望花时间清理能实际移除覆层，以便选项与身体状态一致。
11. 作为玩家，我希望带着现状离开会保留覆层，以便该选择具有持续影响。
12. 作为玩家，我希望保存读取不会重抽对手或材质，以便故事进度可信。
13. 作为玩家，我希望关闭成人偏好仍可完整试玩，以便验收不依赖额外设置。
14. 作为内容作者，我希望知道哪些差异已经编写、哪些能力仍缺失，以便不会误以为系统能无限自由生成。
15. 作为后续执行者，我希望经验草稿区分技术证据与用户评价，以免把测试通过写成内容已获认可。

## Implementation Decisions

- 沿用已确认的完整段落、真实实体绑定、既有资源与覆层结算；复用现有 Event 和行动执行器。
- 小样只准备有效初始存档，并嵌入正常独立游戏入口。资源与起点为明确标注的验收准备，游戏中的所有选择仍走正式事务。
- 不修改世界规则来指定材质；从实际生成的世界及其已声明选敌池中寻找两种真实结果，记录种子与来源。
- 高、低体力对照使用同一世界和相同随机起点。第三份存档只用于展示另一种实际材质，不声称排除了不同世界的一切变量。
- 复用已有示例存档入口并使用独立存档槽，正式存档不参与小样准备。
- 小样单独生成，不加入默认游戏构建，也不改动项目的 Agent 配置。
- 完整事件正文在冲突点结束；地点氛围保留在地点介绍，不追加到事件选择之后。

## Testing Decisions

- 验收边界沿用玩家可见的正式游戏界面与存档导出，内部辅助断言通过既有行动事务和存档校验完成。
- 先例为现有故事复刻集成测试及其桌面、移动浏览器流程。本轮只补小样入口的实际可运行性验证。
- 检查真实地点、属性分支、两种实际材质、付费挣脱、零资源受困、清理与保留、保存恢复，以及正常继续和跳过的完整结算等价。
- 小样不能靠替换屏幕文案制造结果；导出后的时钟、身体、标记和事件位置必须与显示一致。
- 技术测试不能替代人工判断节奏、文笔与趣味。交付后请用户结合直接试玩确认这个验收边界是否足以代表需求，再决定是否扩大故事范围。

## Out of Scope

新增词库或 A/B 拼句工程、运行时自由写作模型、扩大全部故事、多回合闭气、新的战败或恶堕规则、重生成旧世界、经验发布或入库。
